前几章的问题，下楼、跳马、分书、八皇后，每一步都使问题向终点推进：台阶减少、马向右移、分到书的人增多。很多问题不是这样。渡河时，船要把一些人运过去，又要把一些人运回来；走迷宫时会遇到岔路和回头路；拼图、魔方、棋类游戏中，同一个局面可以经由不同的走法反复出现。本章讨论这类多步决策问题的一般建模方法：把问题在每一时刻的情形抽象成一个"状态"，把每一步操作抽象成状态之间的"转移"，求解就变成在所有状态组成的空间中寻找一条从初始状态到目标状态的路径。以人鬼渡河问题为例，本章依次讲怎样把一个游戏数字化、怎样用带访问标记的深度优先搜索避免兜圈子、怎样用广度优先搜索找出步数最少的方案。状态空间搜索是人工智能的基本方法之一，[4.5 人工智能导论](/4.5)会在此基础上讨论启发式搜索与博弈搜索；图的遍历算法本身在 [4.3.10](/4.3.10) 中系统讨论。本章最后对 [4.1.10](/4.1.10) 以来的几种问题求解策略做一个总结。

## 14.1. 多步决策问题的建模

### 14.1.1. 例：人鬼渡河

**例 14.1.1（人鬼渡河）** 3 个人和 3 个鬼在河的东岸，要用一条小船全部渡到西岸。船一次最多载 2 个（两人、两鬼或一人一鬼），至少要有 1 个划船。无论在哪一岸，只要鬼的数目多于人的数目（且该岸有人），人就会被鬼吃掉。船靠岸时，船上的人和鬼算作在岸上。求一种安全的渡河方案，摆渡次数越少越好。

这个问题是经典的"传教士与野人"问题（missionaries and cannibals）的一个版本。与前几章的问题不同，它没有明显的"规模变小的同一问题"：船要来回往返，有时必须把已经过河的人运回去。要让计算机求解，首先要找出过程中哪些量在变化、怎样用数表示它们。

### 14.1.2. 状态与决策的数字化

观察渡河过程，变化的量有：东岸的人数与鬼数、西岸的人数与鬼数、船上的人数与鬼数、船的位置。其中有冗余：两岸的人数之和、鬼数之和都是 3，所以只看东岸就够了；船上的人鬼在靠岸后就算作岸上的，所以不必单独记录。一个时刻的情形可以用三元组

$$
S = (r, g, b)
$$

完整描述：东岸有 $r$ 个人、$g$ 个鬼，$b = 0$ 表示船在东岸，$b = 1$ 表示船在西岸。初始状态为 $(3, 3, 0)$，目标状态为 $(0, 0, 1)$。

一次摆渡的决策是船上载几个人、几个鬼，记为 $d = (u, v)$。满足船的容量的决策只有 5 种：

$$
D = \{(2, 0),\ (1, 0),\ (1, 1),\ (0, 1),\ (0, 2)\}.
$$

船从东岸开往西岸时，东岸的人鬼减少；从西岸开回东岸时，东岸的人鬼增加。于是第 $k$ 次摆渡（$k = 1, 2, \dots$）的状态转移为

$$
(r_k, g_k) = (r_{k-1}, g_{k-1}) + (-1)^k (u_k, v_k), \qquad b_k = 1 - b_{k-1},
$$

$k$ 为奇数时船从东往西，$k$ 为偶数时从西往东。新状态合法的条件是：$0 \leq r, g \leq 3$（运走的人鬼不能多于岸上已有的），并且两岸都安全：东岸 $r = 0$ 或 $r \geq g$，西岸 $3 - r = 0$ 或 $3 - r \geq 3 - g$。对 3 人 3 鬼的情形，两个条件合起来就是

$$
r = 0 \quad\text{或}\quad r = 3 \quad\text{或}\quad r = g.
$$

把船的位置 $b$ 放进状态是必要的：同样是东岸 2 人 2 鬼，船在东岸与船在西岸时能做的决策完全不同，必须看作两个状态。

### 14.1.3. 状态空间

把这种建模方法抽象出来，就得到求解多步决策问题的一般框架。

**定义 14.1.1（状态空间）** 用一组变量描述问题在某一时刻的情形，称为**状态**；一个状态在一次操作下变为另一个状态，称为状态转移。由所有可能的状态、所有合法的转移、初始状态和目标状态组成的模型称为问题的**状态空间**。求解问题就是在状态空间中找出一条从初始状态到某个目标状态的转移序列。

把状态画成结点、合法的转移画成有向边，状态空间就是一张有向图（状态图）；在人鬼渡河问题中，每次摆渡都可以原样开回去，所以边是成对出现的。人鬼渡河的状态空间中，从初始状态出发能到达的合法状态只有 16 个。这张图中有环：$(3, 3, 0) \to (2, 2, 1) \to (3, 3, 0)$ 就是"一人一鬼过去，再一起回来"。前几章的决策树之所以没有环，是因为每一步都让某个量单调变化；一旦有环，盲目的递归就可能永远兜圈子。

| 要素 | 人鬼渡河 | 跳马（[4.1.12](/4.1.12)） | 八皇后 |
|---|---|---|---|
| 状态 | $(r, g, b)$ | 马的坐标 $(x, y)$ | 前 $k$ 行皇后的位置 |
| 操作 | 5 种载法 | 4 种跳法 | 第 $k + 1$ 行的 8 个列 |
| 合法条件 | 人数不少于鬼数 | 不出棋盘 | 不互相攻击 |
| 初始 / 目标 | $(3,3,0)$ / $(0,0,1)$ | $(0,0)$ / $(8,4)$ | 空棋盘 / 放满 8 行 |
| 状态图有环吗 | 有 | 无（只向右跳） | 无（逐行放置） |

## 14.2. 深度优先搜索

### 14.2.1. 用访问标记避免兜圈子

人鬼渡河可以看作一种特殊的"跳马"：棋盘是状态空间，跳法是 5 种决策。照搬 [4.1.12](/4.1.12) 的递归枚举，从当前状态出发依次尝试每种决策，对得到的合法新状态递归。唯一需要补充的是：因为状态图中有环，要记录哪些状态已经访问过，遇到访问过的状态就不再进入。这就是在状态图上做**深度优先搜索**。

```cpp tab
#include <array>
#include <iostream>
#include <vector>

struct State { int r, g, b; };              // people and ghosts on the east bank; boat side

constexpr std::array<std::array<int, 2>, 5> kLoads = {{{2, 0}, {1, 0}, {1, 1}, {0, 1}, {0, 2}}};
bool visited[4][4][2] = {};
std::vector<State> path;

bool safe(int r, int g) {
    return 0 <= r && r <= 3 && 0 <= g && g <= 3 && (r == 0 || r == 3 || r == g);
}

bool dfs(State s) {
    if (s.r == 0 && s.g == 0 && s.b == 1) return true;   // everyone is on the west bank
    int sign = (s.b == 0) ? -1 : +1;                     // east -> west removes people
    for (auto [u, v] : kLoads) {
        State t{s.r + sign * u, s.g + sign * v, 1 - s.b};
        if (!safe(t.r, t.g) || visited[t.r][t.g][t.b]) continue;
        visited[t.r][t.g][t.b] = true;                   // never enter a state twice
        path.push_back(t);
        if (dfs(t)) return true;                         // stop at the first solution
        path.pop_back();
    }
    return false;
}

int main() {
    State start{3, 3, 0};
    visited[3][3][0] = true;
    path.push_back(start);
    if (dfs(start)) {
        for (auto [r, g, b] : path) std::cout << '(' << r << ',' << g << ',' << b << ") ";
        std::cout << '\n' << path.size() - 1 << " crossings\n";
    }
}
```

```python tab
LOADS = [(2, 0), (1, 0), (1, 1), (0, 1), (0, 2)]
State = tuple[int, int, int]        # people and ghosts on the east bank; boat side

def safe(r: int, g: int) -> bool:
    return 0 <= r <= 3 and 0 <= g <= 3 and (r in (0, 3) or r == g)

def dfs(s: State, path: list[State], visited: set[State]) -> bool:
    r, g, b = s
    if (r, g, b) == (0, 0, 1):                       # everyone is on the west bank
        return True
    sign = -1 if b == 0 else +1                      # east -> west removes people
    for u, v in LOADS:
        t = (r + sign * u, g + sign * v, 1 - b)
        if not safe(t[0], t[1]) or t in visited:
            continue
        visited.add(t)                               # never enter a state twice
        path.append(t)
        if dfs(t, path, visited):                    # stop at the first solution
            return True
        path.pop()
    return False

start = (3, 3, 0)
path = [start]
if dfs(start, path, {start}):
    print(*path)
    print(len(path) - 1, "crossings")
```

与 [4.1.12](/4.1.12) 的**回溯**不同，这里访问标记在回退时不撤销：如果从某个状态出发找不到解，以后经由别的路径再到达它，也同样找不到，没有必要再试。访问标记本质上是一种备忘录（[4.1.10](/4.1.10)），只是它记住的不是子问题的值，而是"这个状态已经探索过"。每个状态至多进入一次，所以搜索量不超过状态数乘以决策数。

按上面的决策顺序，深度优先搜索恰好找到一个 11 次摆渡的方案。但这是巧合：深度优先搜索只保证找到某一条路径，不保证它最短；换一种决策的尝试顺序，找到的方案可能更长。

### 14.2.2. 迭代写法

深度优先搜索也可以不用递归：把"待探索的状态"放进一个栈，每次取出栈顶的状态，把它的未访问的后继压入栈中。这就是用显式的栈代替**调用栈**（[4.3.4](/4.3.4)）。状态空间很大、搜索很深时，迭代写法可以避免**栈溢出**和 Python 的递归深度限制。

## 14.3. 广度优先搜索

要求摆渡次数最少，就要换一种搜索顺序：先找出所有 1 步能到达的状态，再找出所有 2 步能到达的状态，依此类推，一层一层向外扩展。第一次到达目标状态时，所用的步数一定最少。这就是**广度优先搜索**。实现时用一个队列：先进入队列的状态先被扩展，因此状态按"离初始状态的步数"从小到大被处理。为了输出方案，再为每个状态记录它是从哪个状态转移来的（前驱），到达目标后沿前驱倒推回初始状态。

```cpp tab
#include <algorithm>
#include <array>
#include <iostream>
#include <map>
#include <queue>
#include <vector>

using State = std::array<int, 3>;           // {people east, ghosts east, boat side}

bool safe(int r, int g) {
    return 0 <= r && r <= 3 && 0 <= g && g <= 3 && (r == 0 || r == 3 || r == g);
}

int main() {
    constexpr std::array<std::array<int, 2>, 5> loads = {{{2, 0}, {1, 0}, {1, 1}, {0, 1}, {0, 2}}};
    const State start{3, 3, 0}, goal{0, 0, 1};
    std::map<State, State> parent{{start, start}};   // also serves as the visited set
    std::queue<State> frontier;
    frontier.push(start);
    while (!frontier.empty()) {
        State s = frontier.front();
        frontier.pop();
        if (s == goal) break;
        int sign = (s[2] == 0) ? -1 : +1;
        for (auto [u, v] : loads) {
            State t{s[0] + sign * u, s[1] + sign * v, 1 - s[2]};
            if (!safe(t[0], t[1]) || parent.contains(t)) continue;
            parent[t] = s;                           // reached for the first time
            frontier.push(t);
        }
    }
    std::vector<State> path;
    for (State s = goal; s != start; s = parent[s]) path.push_back(s);
    path.push_back(start);
    std::reverse(path.begin(), path.end());
    for (auto [r, g, b] : path) std::cout << '(' << r << ',' << g << ',' << b << ") ";
    std::cout << '\n' << path.size() - 1 << " crossings\n";  // 11
}
```

```python tab
from collections import deque

LOADS = [(2, 0), (1, 0), (1, 1), (0, 1), (0, 2)]

def safe(r: int, g: int) -> bool:
    return 0 <= r <= 3 and 0 <= g <= 3 and (r in (0, 3) or r == g)

start, goal = (3, 3, 0), (0, 0, 1)
parent = {start: None}               # also serves as the visited set
frontier = deque([start])
while frontier:
    s = frontier.popleft()
    if s == goal:
        break
    r, g, b = s
    sign = -1 if b == 0 else +1
    for u, v in LOADS:
        t = (r + sign * u, g + sign * v, 1 - b)
        if safe(t[0], t[1]) and t not in parent:
            parent[t] = s            # reached for the first time
            frontier.append(t)

path = []
s = goal
while s is not None:
    path.append(s)
    s = parent[s]
path.reverse()
print(*path)
print(len(path) - 1, "crossings")    # 11
```

最少需要 11 次摆渡。用 $(r, g)$ 表示东岸的人数和鬼数，一种最优方案如下（箭头上是船上的人数与鬼数，奇数次向西、偶数次向东）：

```mermaid
flowchart LR
    s0["(3,3) 船在东"] -->|"1 人 1 鬼 →"| s1["(2,2)"]
    s1 -->|"← 1 人"| s2["(3,2)"]
    s2 -->|"2 鬼 →"| s3["(3,0)"]
    s3 -->|"← 1 鬼"| s4["(3,1)"]
    s4 -->|"2 人 →"| s5["(1,1)"]
    s5 -->|"← 1 人 1 鬼"| s6["(2,2)"]
    s6 -->|"2 人 →"| s7["(0,2)"]
    s7 -->|"← 1 鬼"| s8["(0,3)"]
    s8 -->|"2 鬼 →"| s9["(0,1)"]
    s9 -->|"← 1 人"| s10["(1,1)"]
    s10 -->|"1 人 1 鬼 →"| s11["(0,0) 船在西"]
```

注意第 6 步把一人一鬼运回了东岸，状态 $(2, 2)$ 又出现了一次，只是船的位置不同。正是这种"后退一步"的操作使问题有了难度，也说明了为什么船的位置必须是状态的一部分。

两种搜索的对比如下：

| | 深度优先搜索 | 广度优先搜索 |
|---|---|---|
| 扩展顺序 | 沿一条路走到底，再回溯 | 按离起点的步数逐层扩展 |
| 数据结构 | 栈（或递归的调用栈） | 队列 |
| 找到的解 | 某一个解，不一定最短 | 步数最少的解 |
| 内存 | 与搜索深度成正比 | 与一层的状态数成正比，可能很大 |
| 适用 | 求所有解（配合回溯）、判断是否有解 | 求最少步数 |

## 14.4. 状态空间搜索的推广

人鬼渡河的状态空间只有十几个状态，任何搜索方法都能瞬间完成。实际问题的状态空间往往大得多：15 数码拼图约有 $10^{13}$ 个状态，魔方约有 $4.3 \times 10^{19}$ 个，国际象棋和围棋则大到无法枚举。这时有几个方向：

- **剪枝**与对称性：像八皇后那样尽早排除不可行的状态，利用对称性合并等价的状态。
- 启发式搜索：根据对"离目标还有多远"的估计，优先扩展更有希望的状态，代表算法是 A\* 搜索。估计得当时，它既能保证找到最短路径，又只探索状态空间的一小部分。
- 带权的最短路：若每一步的代价不同（如路程、时间），广度优先搜索推广为 Dijkstra 算法（[4.3.11](/4.3.11)）。
- 博弈搜索：两个对手轮流决策的游戏（棋类），需要考虑对手的最优应对，用极小化极大搜索和 α-β 剪枝。

这些方法是 [4.5 人工智能导论](/4.5) 的内容。本章的意义在于建模：一旦把问题表示成状态空间，就可以使用一整套通用的搜索算法，而不必为每个问题单独设计解法。

## 小结：问题求解策略

[4.1.10](/4.1.10) 至本章的几种策略，都是从"把问题化为更小或更近的问题"这一想法出发的，它们的区别在于子问题之间的关系：

| 策略 | 子问题的结构 | 典型例子 | 章节 |
|---|---|---|---|
| 减治 | 一个更小的子问题 | 阶乘、折半查找、汉诺塔 | [4.1.10](/4.1.10) |
| 分治 | 几个独立的子问题，结果要合并 | 归并排序、快速排序 | [4.1.11](/4.1.11) |
| 枚举与回溯 | 每一步的所有选择构成一棵决策树 | 下楼、分书、八皇后 | [4.1.12](/4.1.12) |
| 动态规划 | 子问题重叠，具有最优子结构 | 钢条切割、矩阵连乘 | [4.1.13](/4.1.13) |
| 状态空间搜索 | 状态图，可能有环 | 人鬼渡河 | 本章 |

拿到一个问题时，可以依次自问：能否用一组变量描述问题在某一时刻的情形（状态）？每一步有哪些选择（决策）？做出选择后状态怎样变化（转移）？哪些状态合法、哪些是目标？求所有解、任意一个解还是最优解？不同的路径是否会到达同一个状态？回答了这些问题，选择哪种策略、用什么数据结构也就清楚了。
