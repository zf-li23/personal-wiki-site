程序设计是用一种机器能够执行的、无歧义的语言，把解决问题的步骤写下来。本课程是计算机学科的第一门课，面向没有编程基础的读者，回答两个问题：一门程序设计语言提供了哪些表达手段，以及怎样借助这些手段想出并写出正确的解法。前一个问题关于数据和控制：数据在计算机中有固定的位数和确定的编码，程序靠分支、循环和函数组织计算，靠**数组**、**指针**和**结构体**组织数据。后一个问题关于算法思想：怎样把一个问题化为规模更小的同类问题，怎样系统地搜索所有可能的方案。课程同时给出 C++ 与 Python 的实现：C++ 贴近机器，能看清数据在内存中的样子；Python 写法简洁，是科学计算与人工智能的通用语言。两者对照，便于分清哪些是程序设计的思想，哪些只是某种语言的语法。

各章的主线是从"语言提供了什么"走向"怎样想出解法"。课程从程序是什么、计算机怎样执行程序、编译与解释的区别讲起，依次引入变量与表达式、分支与循环，并由循环得到第一种算法思想：逐一检验所有可能性的**枚举法**。**函数**把计算打包成可以复用的单位，使问题能够分解为子问题；调试与测试的方法在这时介绍，以便后面写较大的程序。随后是数据的组织：数组与查找、字符串与多维数组、排序，再打开"变量"这个盒子，讨论地址、指针与动态内存，并用指针和结构体搭出**链表**，用文件让数据在程序结束后保存下来。课程的后半部分转向问题求解策略，它们的共同出发点是把问题归结为更小的同类问题：**递归**与**减治**、**分治**（归并排序与快速排序）、在决策树上深度优先搜索的**回溯**、为重叠的子问题记住最优解的**动态规划**，最后把这些策略统一到状态空间搜索之中：把问题的情形抽象成状态，把操作抽象成转移，求解就是寻找一条从初始状态到目标状态的路径。

本课程是后续计算机课程的共同起点。[面向对象程序设计基础](/4.2)把函数和它操作的数据组织成对象，[数据结构与算法](/4.3)系统地分析这里只点到为止的算法复杂度，并讨论链表、栈、树、图等结构的实现；[Python 科学计算](/4.4)在 Python 部分的基础上处理数值数据；状态空间搜索在[人工智能导论](/4.5)中发展为启发式搜索与博弈搜索；计算机内部的细节则留给[计算机组成原理](/4.10)与[操作系统](/4.11)。课程与数学也有直接联系：逻辑表达式就是[离散数学](/1)中的命题逻辑，递归与数学归纳法是同一件事的两面，整数与浮点数的编码在[统计计算与软件](/3.5)中有详细讨论。

对我来说，对编程不再恐惧是从这门课开始的。我修读时还是"古法编程"的年代——这是我对不借助 AI、每一行代码都亲手敲出来的写法的戏称。课程面向完全没有编程基础的学生，前半学期大多在讲语言的基础内容，后半学期则以递归等更需要思维的内容为主。作为一个特别热爱自然和生物的学生，我在中学时期相当抵触"工程"一类人造的东西；这门课和[离散数学](/1)一起，成了我敢于用符号去表示自己所认识的世界的起点。课程选择 C++ 作为第一门语言，我认为是合理的：它有一定的复杂性，能让学生看清程序和数据在机器上的真实样子；它性能好，标准模板库的生态成熟；它也是后面许多门计算机专业课采用的语言。不过，许多生物背景出身的读者并没有接触过 C++，所以本课程也尽量给出 Python 的实践，使不熟悉 C++ 的读者同样能够读懂。

这些年，这门课在 AI 辅助编程的影响下发生了剧烈的变化，我其实也不确定现在的程序设计基础应当怎样学：学生还需要掌握这么多语法细节吗？我的看法是，语法可以放轻，程序设计的思想必须放重。AI 可以替我们写出一个循环或一个函数，却不能替我们决定怎样把问题分解成子问题、用什么数据表示问题的状态、一个递归是否终止；而要判断 AI 写出的代码是否正确，仍然要求读者能读懂代码、能设计测试（见 [AI 辅助编程](/4.2.14)）。因此本课程尽量淡化某一种语言独有的细节，把篇幅留给面向过程的程序设计思想和问题求解策略。
