前几章把变量当作"有名字的盒子"：给它赋值、读它的值，不必关心盒子放在哪里。本章打开这个盒子：每个变量都占据内存中的一段字节，有自己的地址；保存地址的变量就是指针。指针让程序可以间接地访问数据、在运行时按需申请内存、用节点和链接搭建任意形状的数据结构（下一章的链表，以及 [4.3 数据结构与算法](/4.3) 中的树与图）。指针也是 C++ 程序中最常见的错误来源：越界、悬垂指针和内存泄漏都与它有关。本章先讲指针的含义和运算，再讲数组与指针的关系、程序的内存分区和动态内存，最后讲常见错误和现代 C++ 的规避办法。智能指针与 RAII 将在 [4.2.4](/4.2.4) 和 [4.2.12](/4.2.12) 详细讨论；本章末尾对照 Python 的做法：Python 没有指针，但"名字引用对象"的模型恰好可以用指针来理解。

## 8.1. 地址与指针

### 8.1.1. 变量的地址

内存可以看作一长串按字节编号的存储单元，编号就是地址。一个变量由三部分组成：名字（给人读的标识符）、地址（它在内存中的起始位置）和值（那段字节中存放的内容）。编译之后名字就消失了，机器只认地址和值。

C++ 用取地址运算符 `&` 得到变量的地址，用 `sizeof` 得到它占用的字节数：

```cpp
#include <iostream>

int main() {
    int n = 8;
    double x = 3.5;
    std::cout << "n: address " << &n << ", size " << sizeof n << '\n';
    std::cout << "x: address " << &x << ", size " << sizeof x << '\n';
}
```

地址通常以十六进制显示（如 `0x7ffd5c3a1e4c`），每次运行可能不同：现代操作系统会随机化程序的内存布局，以增加攻击者利用漏洞的难度。

### 8.1.2. 指针变量

**定义 8.1.1（指针）** 值为某个对象的地址的变量称为**指针**。指向类型 `T` 的对象的指针，其类型写作 `T*`。对指针 `p` 应用解引用运算符 `*`，得到 `p` 所指向的对象 `*p`；不指向任何对象的指针称为**空指针**，在 C++11 以后写作 `nullptr`。

```cpp
int n = 8;
int* p = &n;     // p holds the address of n
*p = 10;         // writes through p: now n == 10
int* q = nullptr; // a null pointer; *q would be undefined behaviour
```

`int* p` 中的 `*` 是类型的一部分，表达式 `*p` 中的 `*` 是运算符，二者含义不同。一条声明里写 `int* p, q;` 时只有 `p` 是指针、`q` 是 `int`，因此一行只声明一个指针。旧代码中的 `NULL` 和 `0` 也表示空指针，但它们本质上是整数，在函数重载时可能选错版本；现代 C++ 一律用 `nullptr`。

指针的第一个用途是让函数修改调用者的变量。按**值传递**时函数得到的是实参的副本（见 [4.1.4](/4.1.4)），传入地址则可以通过解引用改写原变量：

```cpp
#include <iostream>

void swap_values(int* a, int* b) {
    int t = *a;
    *a = *b;
    *b = t;
}

int main() {
    int x = 1, y = 2;
    swap_values(&x, &y);
    std::cout << x << ' ' << y << '\n';  // 2 1
}
```

C++ 还提供了引用 `int&`，写起来像普通变量、底层通常也用地址实现，函数参数中一般优先用引用（[4.2.6](/4.2.6)）；指针的独有之处在于它可以为空、可以改为指向别的对象、可以做算术。

### 8.1.3. 指针运算与 const

指针可以加减整数：若 `p` 指向**数组**中的某个元素，`p + k` 指向其后第 `k` 个元素。地址实际增加 `k * sizeof(T)` 个字节，因此指针的类型决定了"一步"有多长。同一数组中的两个指针可以相减（得到相隔的元素个数）和比较大小。指针算术只在同一个数组（及其末尾之后一个位置）内有定义，越出这个范围就是未定义行为（§8.4）。

`const` 放在 `*` 的哪一侧，限制的对象不同：

| 声明 | 能否改 `*p` | 能否改 `p` | 读法 |
|---|---|---|---|
| `const int* p` | 否 | 能 | 指向常量的指针 |
| `int* const p` | 能 | 否 | 常量指针 |
| `const int* const p` | 否 | 否 | 指向常量的常量指针 |

从右往左读声明最不容易出错：`int* const p` 读作"p 是一个常量，它是指向 int 的指针"。函数只读取指针所指的数据时，参数写成 `const T*`，既表达意图，又让编译器阻止误写。

## 8.2. 数组与指针

### 8.2.1. 数组名与指针

**数组**的元素在内存中连续存放，下标相邻的元素地址也相邻，相差 `sizeof(元素类型)` 个字节。在大多数表达式中，数组名会自动转换为指向首元素的指针，这称为数组到指针的退化（array-to-pointer decay）。于是对 `int a[5]` 有

$$
a[i] \equiv *(a + i), \qquad a + i \equiv \&a[i],
$$

下标运算本身就是用指针算术定义的。反过来，指向数组元素的指针也可以用下标：`p[i]` 即 `*(p + i)`。

数组名并不是指针变量。两个例外暴露了区别：`sizeof a` 给出整个数组的字节数，而 `sizeof p` 只是一个地址的字节数（64 位平台上为 8）；数组名不能被赋值或自增。

```cpp
#include <iostream>

int main() {
    int a[5] = {1, 2, 1, 2, 9};
    int* p = a;                       // decay: p == &a[0]
    std::cout << sizeof a << ' ' << sizeof p << '\n';  // 20 8 on a 64-bit platform
    for (int* q = a; q != a + 5; ++q) // a pointer used as a loop variable
        std::cout << *q << ' ';
    std::cout << '\n' << p[2] << ' ' << *(a + 2) << '\n'; // 1 1
}
```

### 8.2.2. 数组作为函数参数

数组作函数参数时同样退化为指针：`void f(int a[])`、`void f(int a[10])` 与 `void f(int* a)` 完全等价，函数内部的 `sizeof a` 只是指针的大小，数组的长度信息丢失了。因此传统写法总是多传一个长度参数 `f(a, n)`。现代 C++ 有更好的选择：

- 长度可变的序列用 `std::vector<T>`，按引用传递（`const std::vector<T>&`），长度随对象一起走；
- 只需"看一段连续元素"的函数用 C++20 的 `std::span<const T>`，它就是"指针 + 长度"的打包，可以接受内置数组、`std::vector` 和 `std::array`。

```cpp
#include <iostream>
#include <span>
#include <vector>

int sum(std::span<const int> xs) {  // pointer + length in one object
    int s = 0;
    for (int x : xs) s += x;
    return s;
}

int main() {
    int a[] = {1, 2, 3};
    std::vector<int> v = {4, 5, 6, 7};
    std::cout << sum(a) << ' ' << sum(v) << '\n';  // 6 22
}
```

### 8.2.3. 多维数组的内存布局

C++ 的二维数组 `int m[3][4]` 是"3 个长度为 4 的数组"组成的数组，按行优先（row-major）连续存放：`m[i][j]` 位于首地址之后第 $4i + j$ 个 `int`。正因为编译器要用列数计算偏移，二维数组作参数时必须写明列数：`void f(int m[][4], int rows)`，此时形参的真实类型是 `int (*)[4]`，即指向长度为 4 的数组的指针。

注意两种相似声明的区别：

| 声明 | 含义 |
|---|---|
| `int (*p)[4]` | 一个指针，指向"4 个 int 组成的数组" |
| `int* p[4]` | 一个数组，有 4 个元素，每个元素是 `int*` |

在需要把矩阵传给函数的场合，现代写法是把它存为一维 `std::vector<double>`，按 `i * cols + j` 访问；这既保持连续存储（对缓存友好），又不必和这些类型打交道。C++23 的 `std::mdspan` 为这种"一维存储、多维访问"提供了标准的视图。

## 8.3. 动态内存

### 8.3.1. 内存分区

一个运行中的程序，其内存大致分为四个区域，变量放在哪个区域决定了它的**生存期**：

| 区域 | 存放什么 | 何时分配与释放 | 特点 |
|---|---|---|---|
| 代码区 | 编译后的机器指令 | 程序加载时 | 只读 |
| 静态区（数据区） | 全局变量、`static` 变量、字符串字面量 | 程序开始到结束 | 未显式初始化的被置零 |
| 栈区 | 局部变量、函数参数、返回地址 | 函数调用时自动分配，返回时自动释放 | 快，但容量有限（常见为几 MB） |
| 堆区 | 用 `new` 申请的对象 | 程序员显式申请和释放 | 容量大，生存期由程序控制 |

每次函数调用在栈区压入一个**栈帧**，存放这次调用的参数和局部变量；函数返回时栈帧弹出，其中的变量随之失效。这就是 [4.1.4](/4.1.4) 中**调用栈**的物理实现，[4.1.10](/4.1.10) 的递归也依赖它。栈区的大小在程序启动时就固定了，递归过深或在函数里定义过大的局部数组（如 `int a[10000000];`）会导致**栈溢出**。

### 8.3.2. new 与 delete

栈上对象的大小必须在编译时确定，生存期也被函数调用锁死。当数组长度要到运行时才知道，或者对象要比创建它的函数活得更久时，就需要在堆上分配。

**定义 8.3.1（动态内存分配）** 在程序运行时按需向系统申请一块内存、用完后再显式归还的做法称为**动态内存分配**。C++ 中 `new T` 在堆上创建一个 `T` 类型的对象并返回它的地址，`new T[n]` 创建 `n` 个元素的数组（`n` 可以是变量）；用 `delete p` 和 `delete[] p` 分别释放它们。

```cpp
#include <iostream>

int main() {
    int n;
    std::cin >> n;
    int* a = new int[n];          // size known only at run time
    for (int i = 0; i < n; ++i) a[i] = i * i;
    std::cout << a[n - 1] << '\n';
    delete[] a;                   // every new[] needs exactly one delete[]
    a = nullptr;                  // do not keep a dangling address
}
```

规则很简单，遵守却难：`new` 与 `delete` 配对、`new[]` 与 `delete[]` 配对，每块内存恰好释放一次，释放后不再使用。

二维动态数组的传统做法是两步分配：先分配一个由 `m` 个指针组成的数组，再为每个指针分配一行；释放时严格按相反的顺序进行：

```cpp
int** e = new int*[m];               // step 1: an array of m row pointers
for (int i = 0; i < m; ++i)
    e[i] = new int[n];               // step 2: one row of n ints for each pointer
// ... use e[i][j] ...
for (int i = 0; i < m; ++i) delete[] e[i];  // release the rows first
delete[] e;                                  // then the array of pointers
```

这种结构的各行在内存中并不连续，分配和释放都要循环，任何一步出错都会泄漏。它的价值在于帮助理解"指向指针的指针"；实际编程用下一小节的写法。

### 8.3.3. 现代写法

手工管理内存的根本问题是：释放的责任落在程序员身上，而一个函数可能有多个出口（`return`、异常），任何一个出口忘了 `delete` 就会出错。现代 C++ 的原则是让对象自己管理资源，离开作用域时由析构函数自动释放（这一思想称为 RAII，见 [4.2.4](/4.2.4)）：

| 需求 | 手工写法 | 现代写法 |
|---|---|---|
| 运行时确定长度的数组 | `new T[n]` / `delete[]` | `std::vector<T> a(n);` |
| 矩阵 | `new T*[m]` + 循环 | `std::vector<T> a(m * n);`，按 `a[i * n + j]` 访问 |
| 字符串 | `new char[len + 1]` | `std::string` |
| 单个堆对象（独占） | `new T` / `delete` | `auto p = std::make_unique<T>();` |
| 多处共享的堆对象 | 手工计数 | `std::shared_ptr<T>` |

`std::unique_ptr` 与 `std::shared_ptr` 称为智能指针，[4.2.12](/4.2.12) 详细讨论。经验法则是：业务代码中不出现裸的 `new` 和 `delete`；裸指针 `T*` 只用来"观察"一个由别人拥有的对象，不负责释放它。学习裸指针仍然必要：标准容器、智能指针和下一章的链表都建立在它之上，调试时看到的也是地址。

## 8.4. 常见的内存错误

C++ 不检查指针是否有效。对无效指针的读写属于**未定义行为**（[4.1.2](/4.1.2)）：程序可能崩溃，可能"看起来正常"，也可能悄悄破坏别的数据，而且换一个编译器或优化级别表现就不同。下面是最常见的几类：

**定义 8.4.1** 指针所指向的对象已经被释放或已经结束生存期，而指针仍保存着原来的地址，这样的指针称为**悬垂指针**。程序中动态分配的内存不再被任何指针引用、却没有被释放，因而在程序结束前再也无法回收，称为**内存泄漏**。

| 错误 | 典型代码 | 后果 |
|---|---|---|
| 越界访问 | `int a[30]; a[30] = 1;` | 改写相邻变量，常常在别处表现出来 |
| 未初始化的指针 | `int* p; *p = 1;` | 写到一个随机地址 |
| 解引用空指针 | `int* p = nullptr; *p = 1;` | 通常立即崩溃（段错误） |
| 悬垂指针：释放后使用 | `delete[] a; a[0] = 1;` | 可能读到旧值，也可能破坏堆 |
| 悬垂指针：返回局部变量的地址 | `int* f() { int x = 1; return &x; }` | 栈帧已弹出，地址失效 |
| 重复释放 | `delete p; delete p;` | 破坏堆的管理结构 |
| 内存泄漏 | 在循环里 `new` 却不 `delete`；覆盖唯一的指针 | 长时间运行的程序内存不断增长 |
| `new[]` 与 `delete` 混用 | `int* a = new int[4]; delete a;` | 未定义行为 |

释放后使用的错误特别隐蔽：`delete[]` 并不会改变指针变量的值，也不一定立即清除那块内存，所以紧接着读 `a[0]` 往往还能读出旧值，程序"看起来正常"，直到这块内存被重新分配给别的对象。

应对的办法分三层：

1. 用现代写法从根本上避免：容器、`std::string` 和智能指针管理内存，`std::span` 或引用代替"指针 + 长度"；用 `.at(i)` 代替 `[i]` 可以在越界时抛出异常。
2. 让编译器帮忙：打开警告（`-Wall -Wextra`），指针声明时立即初始化（没有对象可指时用 `nullptr`）。
3. 用工具检测：编译时加 `-fsanitize=address,undefined`（AddressSanitizer 与 UBSan，GCC 与 Clang 都支持，MSVC 支持前者），程序在越界、释放后使用、泄漏发生的那一刻就报告出错的代码行和内存来历；Linux 上的 Valgrind 不需要重新编译也能检查。**调试器**的内存窗口可以直接观察某个地址的内容（[4.1.5](/4.1.5)）。

```bash
g++ -std=c++20 -g -fsanitize=address,undefined main.cpp && ./a.out
```

## 8.5. Python 对照

Python 没有指针和地址运算，但它的变量模型可以用指针来理解：Python 的变量是名字，名字引用对象。赋值 `b = a` 不复制对象，只是让名字 `b` 也引用 `a` 所引用的那个对象，相当于复制了一个指针。`id(x)` 返回对象的标识（CPython 中就是对象的地址），`a is b` 判断两个名字是否引用同一个对象。

这件事是否"看得出来"取决于对象是否可变：整数、浮点数、字符串、元组是不可变的，任何"修改"都会创建新对象再让名字重新引用它，因此共享不会造成意外；列表、字典、集合是可变的，通过一个名字修改，另一个名字也看得到。

```python
a = [1, 2, 3]
b = a            # b and a refer to the same list
b.append(4)
print(a, a is b)  # [1, 2, 3, 4] True

s = "abc"
t = s
t += "d"         # creates a new string; s is unchanged
print(s, t)      # abc abcd

grid = [[0] * 3] * 3      # three references to ONE row
grid[0][0] = 1
print(grid)               # [[1, 0, 0], [1, 0, 0], [1, 0, 0]]
grid = [[0] * 3 for _ in range(3)]  # three distinct rows
```

最后一个例子是初学者最常见的 Python 错误之一，它的原因与 C++ 中两个指针指向同一块内存完全相同。函数参数也按同样的方式传递：函数得到的是对象的引用，在函数内修改可变参数会影响调用者，给参数名重新赋值则不会（[4.1.4](/4.1.4)）。需要独立的副本时用 `list(a)`、`a.copy()` 或 `copy.deepcopy(a)`（[4.2.6](/4.2.6)）。

Python 的列表在内存中是一个连续的"引用数组"，每个元素是指向某个对象的指针，所以同一个列表可以存放不同类型的对象，但数值数据也因此不像 C++ 数组那样紧凑；大规模数值计算用 NumPy 的连续数组（[4.4.2](/4.4.2)）。

Python 程序员不必释放内存，这由垃圾回收（garbage collection）完成，即运行时系统自动找出不再能被程序访问的对象并回收其内存。CPython 的主要机制是引用计数：每个对象记录有多少个引用指向它，计数降为 0 时立即回收；此外还有一个周期性运行的循环垃圾回收器，专门处理互相引用、计数永远不为 0 的对象组。因此 Python 中不会出现悬垂指针和重复释放；但若一个长期存在的容器（如全局的缓存字典）一直持有不再需要的对象，内存同样会持续增长，这是垃圾回收语言中的"内存泄漏"。

## 小结

| 概念 | C++ | Python |
|---|---|---|
| 间接访问 | 指针 `T*`，`&` 取地址，`*` 解引用 | 名字引用对象，赋值即共享引用 |
| 数组与地址 | 连续存放，`a[i] == *(a + i)` | 列表是连续的引用数组 |
| 运行时申请内存 | `new` / `delete`，推荐容器与智能指针 | 创建对象即分配 |
| 释放 | 程序员负责（RAII 自动化） | 垃圾回收 |
| 典型错误 | 越界、悬垂指针、泄漏、重复释放 | 意外共享可变对象、容器持有不需要的对象 |
