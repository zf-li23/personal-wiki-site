Programming means writing down the steps for solving a problem in a language that a machine can execute and that leaves no room for ambiguity. This course is the first in the computer science curriculum and assumes no prior programming experience. It answers two questions: what means of expression a programming language provides, and how to use them to devise and write a correct solution. The first question concerns data and control: data in a computer have a fixed number of bits and a definite encoding, and a program organizes computation with branches, loops and functions and organizes data with **arrays**, **pointers** and **structures**. The second question concerns algorithmic ideas: how to reduce a problem to smaller problems of the same kind, and how to search systematically through all possible solutions. The course gives implementations in both C++ and Python. C++ is close to the machine and shows what data look like in memory; Python is concise and is the common language of scientific computing and artificial intelligence. Seen side by side, the two make it easier to tell which parts are ideas of programming and which are merely the syntax of one language.

The main thread of the chapters runs from "what the language provides" to "how to devise a solution". The course starts from what a program is, how a computer executes it, and the difference between compilation and interpretation, and then introduces variables and expressions, branches and loops. Loops lead to the first algorithmic idea, **exhaustive search**, which checks every possibility one by one. **Functions** package a computation into a reusable unit, so that a problem can be decomposed into subproblems; methods of debugging and testing are introduced at this point, in preparation for larger programs. Next comes the organization of data: arrays and searching, strings and multidimensional arrays, and sorting. The course then opens up the box called a "variable" to discuss addresses, pointers and dynamic memory, builds **linked lists** from pointers and structures, and uses files to keep data after the program ends. The second half of the course turns to problem-solving strategies, which share one starting point, reducing a problem to smaller problems of the same kind: **recursion** and **decrease and conquer**, **divide and conquer** (merge sort and quicksort), **backtracking**, which searches a decision tree depth first, and **dynamic programming**, which remembers the optimal solutions of overlapping subproblems. Finally these strategies are unified in state-space search: situations of the problem are abstracted into states and operations into transitions, so that solving the problem means finding a path from the initial state to a goal state.

This course is the common starting point of later computer science courses. [Object-Oriented Programming](/4.2) organizes functions and the data they operate on into objects. [Data Structures and Algorithms](/4.3) analyzes systematically the complexity of algorithms, which is only touched on here, and discusses the implementation of structures such as linked lists, stacks, trees and graphs. [Scientific Computing with Python](/4.4) builds on the Python part of this course to process numerical data. State-space search is developed into heuristic search and game-tree search in [Introduction to Artificial Intelligence](/4.5), while the internal details of the computer are left to [Computer Organization](/4.10) and [Operating Systems](/4.11). The course is also directly connected to mathematics: a logical expression is the propositional logic of [discrete mathematics](/1), recursion and mathematical induction are two sides of the same thing, and the encoding of integers and floating-point numbers is discussed in detail in [Statistical Computing and Software](/3.5).

For me, losing my fear of programming began with this course. When I took it, it was still the age of "old-school programming", my half-joking name for writing every line of code by hand without the help of AI. The course is aimed at students with no programming background at all: the first half of the semester mostly covers the basics of the language, and the second half deals mainly with material that demands more thinking, such as recursion. As a student who loved nature and living things, I was rather averse in middle school to anything "engineered" and man-made; together with [discrete mathematics](/1), this course became the starting point of my daring to represent with symbols the world I had come to know. I think the choice of C++ as the first language is reasonable. It has a certain complexity, which lets students see what programs and data really look like on the machine. It is also natural enough: programming languages have developed from assembly language to high-level languages, with a style that comes ever closer to the way people think, and C++, as a high-level language, can already express computation in a form close to mathematics and everyday language. It performs well, has a mature ecosystem in the Standard Template Library, and is the language used in many later computer science courses. Many readers with a biology background, however, have never encountered C++, so this course also gives Python practice wherever it can, so that readers unfamiliar with C++ can follow as well.

In recent years this course has changed dramatically under the influence of AI-assisted programming, and I am honestly unsure how programming fundamentals should be learned now: do students still need to master so many details of syntax? My view is that syntax can be given less weight, while the ideas of programming must be given more. AI can write a loop or a function for us, but it cannot decide for us how to decompose a problem into subproblems, what data should represent the state of the problem, or whether a recursion terminates; and to judge whether the code written by AI is correct, readers still need to be able to read code and design tests (see [AI-Assisted Programming](/4.2.14)). This course therefore plays down the details peculiar to any one language as far as it can, and devotes its space to the ideas of procedural programming and to problem-solving strategies.
