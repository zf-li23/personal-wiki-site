本课程讨论的是两种东西的差别：一种是对作者自己能用的程序，另一种是许多人共同开发、更多人使用、并持续多年不断变化的软件。**软件工程**就是研究这一差别的学科，它的核心问题既是技术上的，也是组织上的：团队怎样就要做什么达成一致并把它写下来，怎样使许多人的工作保持一致，系统怎样组织才能达到质量目标、并且修改起来代价低，怎样确信它是正确的，发布之后又怎样让它持续运行。全课程侧重工程思想，而不是具体工具的语法。需要工具时，课程采用当前实践中的工具：版本控制用 Git；实现部分只有一个贯穿的例子，即一个采用**前后端分离**的 Web 应用，前端用 React，后端用 Django。

各章沿着**软件生命周期**展开。引言一章界定这门学科，并按 SWEBOK 的组织概览它的知识体系。**软件过程**一章追溯从**瀑布模型**到**敏捷开发**、Scrum、Kanban 和 **DevOps** 的演变；版本控制一章补上每种过程都依赖的工具：Git 的数据模型与命令、分支策略、**拉取请求**、**代码评审**和**持续集成**。随后，**需求工程**把模糊的愿望变成精确、可检验的需求。**软件架构**借助**质量属性**、设计战术和经典的架构风格，对怎样满足这些需求给出第一个回答；下一章把这些思想推广到分布式的互联网服务，讨论微服务、REST，以及大型网站在性能、可用性和可伸缩性上的模式。接下来三章深入到单个 Web 应用：先是 HTTP、API、认证与 Web 安全，再是把界面看作状态的函数的 React 前端，以及包含模型、视图和 API 的 Django 后端。代码质量与**重构**关注写好之后的代码；两章测试先讲用**白盒测试**和**黑盒测试**设计测试用例，再讲测试自动化、**测试驱动开发**以及从单元测试到验收测试的各个层次。运维以**站点可靠性工程**结束整个周期：**服务等级目标**、**错误预算**、**监控**、事故响应与安全发布。多数章节末尾都讨论 AI 智能体承担部分工作时会有什么变化，最后一章把这些讨论汇总为使用**编程智能体**的工程：规格说明、护栏、**上下文工程**、编排与人工评审，并以本知识库的写作流程作为案例。

本课程以[程序设计基础](/4.1)中的程序设计为前提，单元测试最早出现在那里；类、**设计模式**和 AI 辅助编程见[面向对象程序设计基础](/4.2)。Web 相关的各章建立在[计算机网络原理](/4.12)的协议之上；后端把数据存储在[数据库系统概论](/4.13)的关系数据库中，那里也讨论了大型服务所依赖的索引、分区与事务；[操作系统](/4.11)中的容器与集群则是部署和运维服务的平台。
