本课程研究比单次程序运行存在得更久的数据怎样被描述、查询并保持正确。**数据库管理系统**位于应用程序与数据之间，提供四项保证：用**模式**精确描述数据；提供声明式语言，让用户说明想要什么，而不必说明怎样去找；高效访问远大于内存的数据；在多用户同时工作和机器崩溃时仍保持数据正确。课程的核心问题由此而来：数据应当怎样建模，怎样判断一个模式是好的；声明式的查询怎样变成高效的计算；并发执行与出错的执行怎样表现得像串行的、原子的执行。各章的范围以课程的教学日历为准，讲法以现行的 SQL 与 PostgreSQL 为准，可运行的小例子用 SQLite 与 DuckDB；一个基因表达数据库作为例子贯穿全课程。

各章先从外部看数据库，再把它打开。引言一章给出课程的术语和数据库系统的体系结构。**关系模型**把一切数据表示为关系，用**关系代数**的运算回答查询；**SQL** 把这一模型付诸实践，先是表的定义与单个查询块，再是子查询、递归、窗口函数、视图、访问权限以及在程序中安全地使用 SQL。接下来是设计：**实体–联系模型**用图描述应用领域，再机械地转换为关系模式；完整性约束与**函数依赖**、**规范化**的理论则给出形式化的标准，使模式只记录合法的状态，且每个事实只存一次。从存储开始，视角转为系统的实现者：文件划分为页，由**缓冲池**保存在内存中；**B+ 树**等**索引**在扫描之外提供访问路径；查询处理器借助代价模型和统计信息，在同一查询的许多等价计划与算子算法之间做出选择。**事务**把一组操作组合起来，要求它们表现得像单独运行、要么全做要么全不做：基于**预写日志**的恢复使后一项保证在崩溃后依然成立，基于**两阶段锁**、时间戳或**多版本并发控制**的并发控制使前一项保证在事务交错执行时成立。最后一章按课程大作业的方式，即一个带有自己的 SQL 解析器和文件存储的单用户关系数据库管理系统，把各部分重新组装起来，再概览分布式数据库、NoSQL 系统、分析型数据库、向量数据库，以及数据库在数据分析与生物信息学中的使用。

关系模型建立在[集合论](/1.2)与[数理逻辑](/1.1)的集合、关系与逻辑之上。索引与查询算法沿用[数据结构与算法](/4.3)中的 B 树、散列表和排序，只是改以磁盘页为单位度量；熟悉 [Python 科学计算](/4.4)中数据框的读者会认出连接与分组。数据库管理系统的 SQL 前端是[形式语言与自动机](/4.8)中文法与语法分析的应用。缓冲池、日志与锁对应于[操作系统](/4.11)中的分页、日志文件系统与同步，而以事务作为新的保护单位。反过来，[软件工程](/4.14)把数据库用作 Web 后端和大型互联网服务的存储层，而本课程的大多数读者会在[生物信息学](/7.9)中实际查询生物数据。

我没有修读这门课。在日常科研中我会搭建数据库，但它们通常是静态的，用于展示数据，最多再提供下载，远没有这门课所讲的关系型数据库那样复杂：没有并发的写入，更谈不上事务与恢复。整理这部分知识，是因为以后我可能要承担科研基础设施的搭建工作，届时需要能被许多用户交互读写的数据库。到那时，规范化的模式设计、索引与查询优化、事务的隔离级别，就不再是书本上的概念，而是必须做对的工程决定。
