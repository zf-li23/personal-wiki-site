This course studies how the hardware of a computer executes programs. A programmer sees a set of instructions and their semantics, the **instruction set architecture**; a hardware designer must decide how to implement those instructions with an arithmetic unit, a control unit, memory and input/output devices, and how to make them run faster. The course therefore has two central questions: how the interface between software and hardware should be designed, and how the hardware should be organized behind a given interface. The yardstick for every design is performance: CPU time is the product of instruction count, CPI and clock cycle time. The instruction set, the compiler and the microarchitecture each affect some of the factors, and only the product says which machine is faster.

The chapters first fix the interface and then build an implementation. The overview reviews the development of computers and the **von Neumann architecture**, sets up the layered view from programs down to circuits, and introduces the measurement of performance, the power wall and **Amdahl's law**. The next two chapters treat the interface. The chapter on instruction sets covers instruction formats, the encoding of opcodes, addressing modes, and the two design philosophies of CISC and RISC; the chapter on **RISC-V** presents in full the instruction set used in the course, comparing C programs with compiler-generated assembly to show how the constructs of a high-level language map onto instructions, and covers the calling convention and instruction encoding. The course then turns to implementation. The chapter on data representation explains how the same bit string is interpreted as an integer, a **floating-point number** or a character depending on the instruction, and discusses error detection and correction in storage and transmission; the chapter on the arithmetic unit builds a 32-bit **arithmetic logic unit**, multipliers and dividers, and the steps of floating-point arithmetic on these encodings. Finally, the instruction formats and the arithmetic unit are combined into a **datapath**, and a control unit is added to obtain a single-cycle processor, in which every instruction completes in one clock cycle. The clock cycle of a single-cycle processor is set by the slowest instruction, which is the starting point of multicycle processors and pipelining; these topics, as well as the memory hierarchy, input/output and buses, are not yet included.

Below this course lies [Digital Logic Circuits](/4.9): the gate-level implementations of adders, registers and state machines are there, and the processor labs use its hardware description language on an FPGA. Above it is software: the execution model of programs and the **call stack** are in [Programming Fundamentals](/4.1), the general representation of numbers in computers is in the first chapter of [Statistical Computing and Software](/3.5) ([3.5.1](/3.5.1)), and the **Turing machine** as the theoretical model of computation is in [Formal Languages and Automata](/4.8). The course that follows, [Operating Systems](/4.11), builds on the hardware mechanisms discussed here: privilege modes, exceptions and interrupts, and address translation become the foundations of processes and virtual memory.
