上一章讨论了**指令系统**设计的一般问题，本章完整地介绍一个具体的指令系统：**RISC-V**。它是本课程实验所用的指令系统，也是理解后续章节处理器设计的基础：[4.10.6](/4.10.6) 的单周期处理器、后续章节的流水线都以实现它的一个子集为目标。本章先介绍 RISC-V 的模块化结构和**寄存器**，然后按功能逐类讲授基本整数指令（RV32I，必要时说明 64 位的 RV64I 和乘除法扩展），用 C 程序与 GCC 生成的汇编代码对照说明高级语言的各种结构怎样落实到指令上；接着讲函数调用约定与栈帧，它是 [4.1.4](/4.1.4) 中**调用栈**的机器级实现；最后讲指令怎样编码成 32 位的机器码。本章的汇编代码都用 RISC-V GCC 实测编译过；指令的语义以 RISC-V International 发布的现行规范为准。

## 3.1. RISC-V 概述

### 3.1.1. 历史与特点

**定义 3.1.1（RISC-V）** 由加州大学伯克利分校于 2010 年开始设计、现由非营利组织 RISC-V International 维护的开放的 RISC 指令集体系结构称为 **RISC-V**（读作 risk-five）。

名称中的 V 表示这是伯克利从 1980 年的 RISC I 算起的第五代 RISC 设计。它由 Krste Asanović、David Patterson、Andrew Waterman、Yunsup Lee 等人发起，最初是为了教学和研究：已有的指令系统要么受专利和授权限制，要么背负着几十年的历史包袱。RISC-V 有几个突出的特点：

- 开放：规范以开放许可发布，任何人都可以免费实现、修改和销售 RISC-V 处理器，不需要授权费。标准由 RISC-V International（2015 年成立时名为 RISC-V 基金会，2020 年迁至瑞士并改为现名）通过公开的流程制定。
- 简洁：吸取了此前几代 RISC 的经验，去掉了分支延迟槽、条件码等妨碍后来的实现技术的设计。基本整数**指令集** RV32I 只有 40 条指令，规范只占十几页；作为对照，x86 的手册有五千多页。
- 模块化：一个小而固定的基本指令集，加上可选的标准扩展，从几千门的微控制器到超级计算机都可以只实现自己需要的部分（3.1.2 节）。
- 稳定：已批准（ratified）的部分冻结，以后不再改变，在其上编写的软件可以长期运行。

### 3.1.2. 基本指令集与扩展

RISC-V 的每个实现都由一个基本整数指令集加上若干扩展组成，用字母或名称表示。

| 基本指令集 | 说明 |
|---|---|
| RV32I | 32 位整数指令集，32 个 32 位通用寄存器 |
| RV64I | 64 位整数指令集，寄存器为 64 位，增加 64 位访存与 32 位"字"运算指令 |
| RV32E、RV64E | 嵌入式版本，只有 16 个通用寄存器 |
| RV128I | 128 位版本，尚未冻结 |

寄存器的位数记为 XLEN，RV32 中 XLEN = 32，RV64 中 XLEN = 64。常用的标准扩展：

| 扩展 | 内容 |
|---|---|
| M | 整数乘法与除法 |
| A | 原子操作：load-reserved / store-conditional 与原子读-改-写，用于多处理器同步（[4.11.6](/4.11.6)） |
| F、D、Q | **单精度**、**双精度**、四倍精度浮点，符合 **IEEE 754**（[4.10.4](/4.10.4)），另有 32 个浮点寄存器 `f0`–`f31` |
| C | 压缩指令：常用指令的 16 位编码，使代码缩小约 25%–30%（3.8.8 节） |
| Zicsr、Zifencei | 控制状态寄存器访问指令、指令取指同步指令；原属 I，2019 年拆分出来 |
| B | 位操作（Zba 地址计算、Zbb 基本位操作、Zbs 单位操作），如循环移位、前导零计数 |
| V | 向量扩展：向量长度由硬件决定，同一份程序可以在不同向量长度的硬件上运行 |
| H | 虚拟化（hypervisor）支持（[4.11.9](/4.11.9)） |

IMAFD 加上 Zicsr、Zifencei 合称 G（general），所以 `RV64GC` 就是 `RV64IMAFDC_Zicsr_Zifencei`，这是运行 Linux 的 64 位处理器的常见配置。GCC 用 `-march=rv32im`、`-march=rv64gc` 这样的写法指定目标。为了避免各家任意组合扩展造成的软件碎片化，RISC-V International 还定义了配置文件（profile）：如面向应用处理器的 RVA23（2024 年批准）规定了运行通用操作系统必须支持的扩展集合，其中包括向量扩展 V 与虚拟化扩展 H。早期规划中的一些字母（如十进制浮点 L、用户态中断 N）已经放弃，打包 SIMD 扩展 P 尚未批准。

本课程实验的 ThinPAD 处理器只要求实现 RV32I 的一个子集：运行监控程序基础版本所需的 19 条指令为 `add`、`addi`、`and`、`andi`、`auipc`、`beq`、`bne`、`jal`、`jalr`、`lb`、`lui`、`lw`、`or`、`ori`、`sb`、`slli`、`srli`、`sw`、`xor`；支持中断与异常的版本另加 `csrrc`、`csrrs`、`csrrw`、`ebreak`、`ecall`、`mret`，支持虚拟地址的版本再加 `sfence.vma`。

### 3.1.3. 特权模式与控制状态寄存器

RISC-V 规范分为两卷：非特权规范（unprivileged ISA）定义普通程序可用的指令，特权规范（privileged architecture）定义操作系统和固件所需的机制。特权规范规定了三种特权模式：

| 模式 | 用途 | 是否必需 |
|---|---|---|
| M（machine） | 最高特权，固件与简单嵌入式系统 | 必需 |
| S（supervisor） | 操作系统内核，支持虚拟内存 | 可选 |
| U（user） | 应用程序 | 可选 |

简单的微控制器只实现 M 模式；运行 Linux 的处理器实现 M、S、U 三种模式。处理器的状态与配置保存在控制状态寄存器（control and status register，CSR）中，它们有独立的 12 位地址空间，用 Zicsr 扩展的 `csrrw`、`csrrs`、`csrrc` 等指令读写。例如 `mtvec` 存放异常处理程序的入口，`mepc` 保存发生异常的指令地址，`mcause` 记录异常原因；`cycle`、`instret` 两个**计数器**分别统计**时钟周期**数和已完成的指令数，用户程序用伪指令 `rdcycle`、`rdinstret` 读取它们，两者之比就是程序实际运行的 **CPI**（[4.10.1](/4.10.1#sec-1.4.2)）。`ecall` 指令从 U 模式陷入更高特权的模式，用于系统调用（[4.11.1](/4.11.1)）。异常、中断与特权模式的细节在后续章节中讨论。

## 3.2. 寄存器与汇编语言

### 3.2.1. 寄存器堆

运算指令的操作数只能来自寄存器（load-store 型，[4.10.2](/4.10.2#sec-2.1.3)），所以寄存器的数量和用法是指令系统的核心。

**定义 3.2.1（寄存器堆）** 处理器中由若干个通用寄存器组成、按编号读写的存储部件称为**寄存器堆**（register file）。RV32I 的寄存器堆有 32 个 32 位通用寄存器 `x0`–`x31`（RV64I 中为 64 位），其中 `x0` 恒为 0：读它总得到 0，写它不起作用。

**程序计数器** `pc` 不在寄存器堆中，不能用普通指令直接读写。寄存器堆的硬件实现通常有两个读端口和一个写端口，正好满足"两个源寄存器、一个目的寄存器"的**指令格式**（[4.10.6](/4.10.6)）。为什么是 32 个？寄存器越多，**编译器**越能把变量留在寄存器中；但寄存器堆越大，读出越慢，编号也要占更多的指令位（32 个寄存器需要 5 位，三个寄存器字段共 15 位），这是"越小越快"的折中。`x0` 恒为 0 使许多操作不需要专门的指令：`add x1, x2, x0` 就是寄存器传送，`addi x1, x0, 5` 就是装入常数。

硬件对 `x1`–`x31` 一视同仁，它们的用途由软件约定：每个寄存器有一个 **ABI** 名，汇编程序中通常用 ABI 名书写。

| 寄存器 | ABI 名 | 用途 | 由谁保存 |
|---|---|---|---|
| `x0` | `zero` | 恒为 0 | — |
| `x1` | `ra` | 返回地址 | 调用者 |
| `x2` | `sp` | 栈指针 | 被调用者 |
| `x3` | `gp` | 全局指针 | —（不参与分配） |
| `x4` | `tp` | 线程指针 | —（不参与分配） |
| `x5` | `t0` | 临时寄存器；备用的链接寄存器 | 调用者 |
| `x6`–`x7` | `t1`–`t2` | 临时寄存器 | 调用者 |
| `x8` | `s0` / `fp` | 保存寄存器；帧指针 | 被调用者 |
| `x9` | `s1` | 保存寄存器 | 被调用者 |
| `x10`–`x11` | `a0`–`a1` | 函数参数、返回值 | 调用者 |
| `x12`–`x17` | `a2`–`a7` | 函数参数 | 调用者 |
| `x18`–`x27` | `s2`–`s11` | 保存寄存器 | 被调用者 |
| `x28`–`x31` | `t3`–`t6` | 临时寄存器 | 调用者 |

有 F 或 D 扩展时另有 32 个浮点寄存器，ABI 名为 `ft0`–`ft11`（临时，调用者保存）、`fs0`–`fs11`（被调用者保存）和 `fa0`–`fa7`（参数与返回值）。"由谁保存"一列的含义见 3.7.2 节。

### 3.2.2. 汇编语言程序的格式

RISC-V 的运算指令都写成"一个操作、三个操作数"的形式：

```asm
op   rd, rs1, rs2      # rd = rs1 op rs2
opi  rd, rs1, imm      # immediate form: the second source is a constant
```

`rd` 是目的寄存器，`rs1`、`rs2` 是源寄存器；`#` 之后是注释。一个汇编源文件除了指令，还有标号（label，后跟冒号，代表它所在位置的地址）和以点开头的汇编指示（directive），后者不产生指令，而是告诉汇编器怎样组织输出：`.text`、`.data` 选择代码段或数据段，`.globl` 声明全局符号，`.word`、`.byte`、`.string` 放置数据，`.align` 对齐。

例如 C 语句 `a = (b + c) - (d + e);`，设 `a`–`e` 依次在 `s0`–`s4` 中：

```asm
add  t0, s1, s2        # t0 = b + c
add  t1, s3, s4        # t1 = d + e
sub  s0, t0, t1        # a = (b + c) - (d + e)
```

复杂的表达式被拆成一串只有两个源操作数的指令，中间结果放在临时寄存器中。下面的汇编代码一般写 ABI 名；在说明编码时写 `x` 编号。

## 3.3. 整数运算指令

### 3.3.1. 加法与减法

| 指令 | 含义 | 说明 |
|---|---|---|
| `add rd, rs1, rs2` | `rd = rs1 + rs2` | |
| `sub rd, rs1, rs2` | `rd = rs1 - rs2` | |
| `addi rd, rs1, imm` | `rd = rs1 + imm` | `imm` 是 12 位有符号数，范围 $[-2048, 2047]$，符号扩展到 XLEN 位 |
| `lui rd, imm` | `rd = imm << 12` | 装入 20 位高位立即数（3.6.2 节） |
| `auipc rd, imm` | `rd = pc + (imm << 12)` | 用于 **PC** 相对的地址计算 |

没有 `subi`：减去一个常数就是加上它的相反数，`addi t0, t0, -1`。

RISC-V 的加减法不检测**溢出**，也没有条件码：结果只保留低 XLEN 位，写入目的寄存器（即按模 $2^{\mathrm{XLEN}}$ 的**补码**运算，[4.10.4](/4.10.4)）。这符合 C 语言中无符号整数的语义；有符号整数溢出在 C 中是**未定义行为**，编译器也不检查。需要检测时用一两条额外的分支指令：

```asm
# unsigned overflow of t0 = t1 + t2: the sum is smaller than an operand
add  t0, t1, t2
bltu t0, t1, overflow

# signed overflow in general: (t2 < 0) must equal (t0 < t1)
add  t0, t1, t2
slti t3, t2, 0
slt  t4, t0, t1
bne  t3, t4, overflow
```

第二段的依据是：没有溢出时，$t_0 = t_1 + t_2$，因此 $t_0 < t_1 \iff t_2 < 0$；发生溢出时这个等价恰好被破坏。若已知 `t2` 的符号（如加一个正的立即数），一条 `blt` 就够了。

RV64I 中寄存器是 64 位，C 的 `int` 仍是 32 位。为此 RV64I 增加了 `addw`、`subw`、`addiw` 等"字"运算：只对低 32 位运算，把 32 位结果符号扩展到 64 位写入。例如 RV64 中 `int` 类型的 `*p += 5` 编译为 `lw`、`addiw`、`sw` 三条指令。

### 3.3.2. 逻辑运算与移位

| 指令 | 含义 |
|---|---|
| `and`、`or`、`xor rd, rs1, rs2` | 按位与、或、**异或** |
| `andi`、`ori`、`xori rd, rs1, imm` | 与符号扩展后的 12 位立即数按位运算 |
| `sll rd, rs1, rs2` | 逻辑左移，低位补 0 |
| `srl rd, rs1, rs2` | 逻辑右移，高位补 0 |
| `sra rd, rs1, rs2` | 算术右移，高位补符号位 |
| `slli`、`srli`、`srai rd, rs1, shamt` | 移位位数为立即数 |

移位位数只取 `rs2` 的低 5 位（RV64 为低 6 位），立即数 `shamt` 的范围是 0–31（RV64 为 0–63）。没有按位取反指令：`xori rd, rs, -1`（与全 1 异或）就是取反。`andi` 常用来取出某些位（**掩码**），如 `andi t0, t0, 0xFF` 取最低字节。左移 $k$ 位相当于乘以 $2^k$，编译器用它计算**数组**元素的地址（`slli t0, a1, 2` 即 `i * 4`）；算术右移 $k$ 位相当于除以 $2^k$ 后向负无穷取整，与 C 中整数除法的向零取整在负数时不同，所以编译器对有符号数的 `x / 4` 还要加一个修正。

### 3.3.3. 比较

| 指令 | 含义 |
|---|---|
| `slt rd, rs1, rs2` | 若 `rs1 < rs2`（有符号比较）则 `rd = 1`，否则 `rd = 0` |
| `sltu rd, rs1, rs2` | 同上，无符号比较 |
| `slti`、`sltiu rd, rs1, imm` | 与立即数比较；`sltiu` 中立即数先符号扩展，再按无符号数比较 |

同一个位串作为有符号数和无符号数比较，结果可能不同：

```asm
addi  t0, zero, -1     # t0 = 0xFFFFFFFF
slti  t1, t0, 1        # t1 = 1: as signed, -1 < 1
sltiu t2, t0, 1        # t2 = 0: as unsigned, 2^32 - 1 > 1
```

有符号与无符号的区分在 RISC-V 中出现在三处：比较（`slt` / `sltu`）、条件分支（`blt` / `bltu`，3.5.1 节）、load 的扩展方式（`lb` / `lbu`，3.4.3 节）。加、减、逻辑运算和左移对两者完全相同，这是**补码**表示的好处。`sltiu rd, rs, 1` 在 `rs == 0` 时得 1，因此"等于零"的判断也不需要专门的指令（伪指令 `seqz`）。

### 3.3.4. 乘除法扩展

两个 XLEN 位数的乘积有 $2 \times \mathrm{XLEN}$ 位，M 扩展用两条指令分别取低半部分和高半部分：

| 指令 | 含义 |
|---|---|
| `mul rd, rs1, rs2` | 乘积的低 XLEN 位（有符号、无符号相同） |
| `mulh rd, rs1, rs2` | 乘积的高 XLEN 位，两个操作数都是有符号数 |
| `mulhu rd, rs1, rs2` | 高 XLEN 位，两个操作数都是无符号数 |
| `mulhsu rd, rs1, rs2` | 高 XLEN 位，`rs1` 有符号、`rs2` 无符号 |
| `div`、`divu rd, rs1, rs2` | 商，有符号 / 无符号，向零取整 |
| `rem`、`remu rd, rs1, rs2` | 余数，符号与被除数相同 |

需要完整的乘积时，规范建议写成 `mulh[[s]u] rdh, rs1, rs2` 后紧跟 `mul rdl, rs1, rs2`（源寄存器的顺序相同，且 `rdh` 与 `rs1`、`rs2` 都不同）；同样，需要商和余数时写成 `div` 后紧跟 `rem`。这样**微体系结构**可以把两条指令融合成一次运算。RV64 另有 `mulw`、`divw`、`remw` 等 32 位版本。

除法有两种特殊情况。RISC-V 不为它们产生异常（这样简化了流水线），而是规定了确定的结果，需要时由软件用一条分支检查：

| 情况 | 被除数 $x$ | 除数 | `divu` | `remu` | `div` | `rem` |
|---|---|---|---|---|---|---|
| 除以零 | $x$ | 0 | $2^{\mathrm{XLEN}} - 1$（全 1） | $x$ | $-1$ | $x$ |
| 有符号溢出 | $-2^{\mathrm{XLEN}-1}$ | $-1$ | — | — | $-2^{\mathrm{XLEN}-1}$ | 0 |

`rem` 遵循 C 的语义：商向零取整，余数与被除数同号，如 `-7 / 2 = -3`、`-7 % 2 = -1`；它与数学上取值在 $[0, b)$ 中的模运算在负数时不同。乘除法器的算法与硬件见 [4.10.5](/4.10.5)。

## 3.4. 访存指令

### 3.4.1. 字节寻址与数据对齐

存储器可以看作一个以字节为单位的一维数组，地址从 0 开始，每个**字节**有自己的地址（字节寻址）。RISC-V 规定半字（halfword）为 16 位、字（word）为 32 位、双字（doubleword）为 64 位，一个多字节数据的地址是它最低字节的地址。相邻的字地址相差 4，C 的 `int a[]` 中 `a[i]` 的地址是 `a + 4*i`：C 编译器根据类型自动乘以元素大小，在汇编中则要程序员自己计算。

**定义 3.4.1（数据对齐）** 大小为 $n$ 字节（$n$ 为 2 的幂）的数据存放在地址为 $n$ 的倍数的位置时，称该数据是**对齐**的（aligned），这种要求称为数据对齐（data alignment）；否则称为未对齐（misaligned）。

例如对齐的字的地址最低两位为 0。对齐的数据总是落在同一个存储字（以及同一个高速缓存行、同一个页）之内，一次访问就能完成；未对齐的数据可能跨越两个存储字，需要两次访问再拼接。RISC-V 的基本指令集允许未对齐访问，但它可能很慢，或者被实现为异常再由软件模拟，由执行环境决定；x86 允许未对齐访问，代价也是速度。因此编译器总是按类型对齐变量，结构体中的成员之间可能插入填充字节（[4.1.9](/4.1.9)）。指令本身也必须对齐：没有 C 扩展时指令地址是 4 的倍数，有 C 扩展时是 2 的倍数。

### 3.4.2. 字节序

多字节数据在存储器中按什么顺序存放？

**定义 3.4.2（大端序与小端序）** 多字节数据的最高有效字节存放在最低地址的存储方式称为**大端序**（big-endian）；最低有效字节存放在最低地址的方式称为**小端序**（little-endian）。数据在存储器中的字节排列顺序统称**字节序**（byte order，endianness）。

例如把 32 位数 `0x00000180` 存放在地址 0–3：

| 地址 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| 大端序 | `00` | `00` | `01` | `80` |
| 小端序 | `80` | `01` | `00` | `00` |

RISC-V 是小端序的（特权规范允许实现把数据访问切换为大端序，但指令总是按小端序存放），x86 和绝大多数 ARM 系统也是小端序；网络协议中的多字节字段按大端序传输，称为网络字节序。只要始终按同样大小的单位读写，字节序对程序不可见；按字节访问一个整数、在网络上传输数据、读写二进制文件时，就必须考虑它（[4.1.9](/4.1.9)）。

### 3.4.3. load 与 store 指令

RISC-V 只有 load 和 store 两类指令访问存储器，都用**基址寻址**（[4.10.2](/4.10.2#sec-2.3.2)）：地址 = 基址寄存器 `rs1` + 符号扩展的 12 位位移量，写作 `offset(rs1)`。

| 指令 | 含义 |
|---|---|
| `lw rd, off(rs1)` | 读 32 位字（RV64 中符号扩展到 64 位） |
| `lh`、`lhu rd, off(rs1)` | 读 16 位半字，符号扩展 / 零扩展 |
| `lb`、`lbu rd, off(rs1)` | 读 8 位字节，符号扩展 / 零扩展 |
| `sw rs2, off(rs1)` | 把 `rs2` 的低 32 位写入存储器 |
| `sh`、`sb rs2, off(rs1)` | 写 `rs2` 的低 16 位 / 低 8 位，其余位被忽略 |
| `ld`、`sd`、`lwu` | RV64：读写 64 位双字；读 32 位字并零扩展 |

注意 store 的写法 `sw rs2, off(rs1)`：被写的数据在前，地址在后。例如设数组 `A` 的起始地址在 `s3` 中、变量 `h` 在 `s2` 中，C 语句 `A[10] = h + A[3];` 编译为

```asm
lw   t0, 12(s3)        # t0 = A[3], address s3 + 3*4
add  t0, s2, t0        # t0 = h + A[3]
sw   t0, 40(s3)        # A[10] = t0, address s3 + 10*4
```

load 时要把短数据扩展到寄存器的宽度：C 的 `signed char`、`short` 用 `lb`、`lh` 做符号扩展，`unsigned char`、`unsigned short` 用 `lbu`、`lhu` 做零扩展。设 `s0` 所指的字为 `0x00000180`（小端序，字节依次为 `80 01 00 00`）：

```asm
lb   t0, 1(s0)         # t0 = 0x00000001
lb   t1, 0(s0)         # t1 = 0xFFFFFF80: byte 0x80 is sign-extended
lbu  t2, 0(s0)         # t2 = 0x00000080: zero-extended
sb   t1, 2(s0)         # the word at s0 becomes 0x00800180
```

## 3.5. 控制转移指令

### 3.5.1. 条件分支

**汇编语言**没有语句块，控制流靠转移到标号实现，相当于 C 中的 `goto`。RISC-V 的条件分支指令在一条指令中比较两个寄存器并转移，不依赖条件码：

| 指令 | 转移条件 |
|---|---|
| `beq rs1, rs2, label` | `rs1 == rs2` |
| `bne rs1, rs2, label` | `rs1 != rs2` |
| `blt rs1, rs2, label` | `rs1 < rs2`，有符号 |
| `bge rs1, rs2, label` | `rs1 >= rs2`，有符号 |
| `bltu rs1, rs2, label` | `rs1 < rs2`，无符号 |
| `bgeu rs1, rs2, label` | `rs1 >= rs2`，无符号 |

转移目标用 **PC 相对寻址**，范围是当前指令前后约 4 KiB（3.8.3 节）。`bgt`、`ble` 等是交换操作数得到的伪指令。去掉条件码的好处是，指令之间没有隐含的依赖（x86 中几乎每条运算指令都会改写标志寄存器），流水线和乱序执行更容易实现。

无符号比较有一个常用技巧：数组下标的越界检查 `if (i < 0 || i >= n)` 只需一条 `bgeu i, n, out_of_bounds`，因为负的 `i` 作为无符号数是一个很大的数。

### 3.5.2. 无条件跳转

| 指令 | 含义 |
|---|---|
| `jal rd, label` | `rd = pc + 4`，然后 `pc = label`（PC 相对，范围约 ±1 MiB） |
| `jalr rd, off(rs1)` | `rd = pc + 4`，然后 `pc = (rs1 + off) & ~1` |

"and link"指把下一条指令的地址（返回地址）写入 `rd`，用于函数调用：`jal ra, f` 调用函数 `f`，函数结束时 `jalr zero, 0(ra)` 返回。不需要返回地址时把 `rd` 设为 `zero`，就是普通的跳转：`jal zero, label` 即伪指令 `j label`。`jalr` 的目标地址由寄存器给出，用于函数返回、函数指针、虚函数调用和 `switch` 的跳转表；它把目标的最低位清零，这样目标总是偶数地址。`jalr` 与 `auipc` 配合可以跳到 32 位范围内的任何位置（3.6.2 节）。

分支指令的范围有限，要转移到更远的位置时，汇编器把条件取反，跳过一条 `jal`：

```asm
# beq a0, zero, far    (far is out of branch range) becomes
bne  a0, zero, next
j    far
next:
```

### 3.5.3. 循环与分支的编译

把 C 的控制结构变成分支指令，是编译器最基本的工作。以求和循环为例，GCC 在 `-Og`（只做不影响调试的优化）和 `-O2` 下生成的 RV32 代码：

```c
int sum_n(int n) {
    int s = 0;
    for (int i = 1; i <= n; i++)
        s += i;
    return s;
}
```

```asm
# gcc -march=rv32im -mabi=ilp32 -Og
sum_n:
    mv   a4, a0            # a4 = n
    li   a5, 1             # i = 1
    li   a0, 0             # s = 0
    j    .L5               # test the condition first
.L6:
    add  a0, a0, a5        # s += i
    addi a5, a5, 1         # i++
.L5:
    ble  a5, a4, .L6       # loop while i <= n
    ret                    # the result is in a0
```

```asm
# gcc -march=rv32im -mabi=ilp32 -O2
sum_n:
    ble  a0, zero, .L6     # n <= 0: the loop body never runs
    addi a4, a0, 1         # a4 = n + 1
    li   a5, 1             # i = 1
    li   a0, 0             # s = 0
.L5:
    add  a0, a0, a5
    addi a5, a5, 1
    bne  a5, a4, .L5       # one branch per iteration
    ret
.L6:
    li   a0, 0
    ret
```

两种代码都把循环条件放在循环体之后，每次迭代只执行一条分支。`-O2` 在进入循环前判断一次 $n \le 0$，循环内改用 `bne` 与 $n + 1$ 比较。若把上界改为常数 10，`-O2` 会直接算出结果：整个函数变成 `li a0, 55` 和 `ret`。

`if-else` 的编译方式类似：对条件取反，不满足时跳过 `then` 部分。例如 `return a > b ? a : b;` 在 `-O2` 下编译为

```asm
max:
    mv   a5, a0            # a5 = a
    mv   a0, a1            # assume the result is b
    bge  a1, a5, .L1       # if b >= a, done
    mv   a0, a5            # otherwise the result is a
.L1:
    ret
```

## 3.6. 伪指令与大常数

### 3.6.1. 伪指令

上面的代码中已经出现了 `mv`、`li`、`j`、`ble`、`ret`，它们不是 RISC-V 的真实指令。

**定义 3.6.1（伪指令）** 汇编语言中提供给程序员使用、但没有对应的机器指令，由汇编器翻译成一条或几条真实指令的助记符称为**伪指令**（pseudoinstruction）。

伪指令让汇编程序更易读，又不增加硬件的负担。真实指令的集合是汇编程序员可用的指令集合的子集。常用的伪指令（"实际指令"一列是汇编器的翻译结果，用 `objdump -M no-aliases` 可以看到）：

| 伪指令 | 实际指令 | 含义 |
|---|---|---|
| `nop` | `addi x0, x0, 0` | 空操作 |
| `mv rd, rs` | `addi rd, rs, 0` | 寄存器传送 |
| `not rd, rs` | `xori rd, rs, -1` | 按位取反 |
| `neg rd, rs` | `sub rd, x0, rs` | 取相反数 |
| `seqz rd, rs` | `sltiu rd, rs, 1` | `rd = (rs == 0)` |
| `snez rd, rs` | `sltu rd, x0, rs` | `rd = (rs != 0)` |
| `beqz rs, L`、`bnez rs, L` | `beq rs, x0, L`、`bne rs, x0, L` | 与零比较并转移 |
| `bgt rs, rt, L`、`ble rs, rt, L` | `blt rt, rs, L`、`bge rt, rs, L` | 交换操作数 |
| `bgtu`、`bleu` | `bltu`、`bgeu`（交换操作数） | 无符号版本 |
| `j L` | `jal x0, L` | 跳转 |
| `jr rs` | `jalr x0, 0(rs)` | 跳转到寄存器中的地址 |
| `ret` | `jalr x0, 0(x1)` | 函数返回 |
| `call f` | `auipc x1, %pcrel_hi(f)`<br/>`jalr x1, %pcrel_lo(f)(x1)` | 调用任意远处的函数 |
| `tail f` | `auipc x6, %pcrel_hi(f)`<br/>`jalr x0, %pcrel_lo(f)(x6)` | 尾调用，不保存返回地址 |
| `li rd, imm` | `addi`，或 `lui` 加 `addi` | 装入常数（3.6.2 节） |
| `la rd, sym` | `auipc` 加 `addi` | 装入符号的地址 |

伪指令与汇编指示（`.text`、`.word` 等）不同：伪指令最终产生机器指令，汇编指示不产生指令。链接器还可以在链接时把可以缩短的指令序列"松弛"（relax）为更短的形式，例如目标足够近时把 `call` 的两条指令换成一条 `jal`。

### 3.6.2. 装入常数与地址

I 型指令的立即数只有 12 位。32 位常数要分成高 20 位和低 12 位两部分，用 `lui` 装入高 20 位（低 12 位清零），再用 `addi` 加上低 12 位：

```asm
lui  a0, 0x87654        # a0 = 0x87654000
addi a0, a0, 0x321      # a0 = 0x87654321
```

一个陷阱是 `addi` 的立即数是有符号的。要得到 `0xDEADBEEF`，若直接写 `lui a0, 0xDEADB` 与 `addi a0, a0, 0xEEF`，后者的 12 位立即数 `0xEEF` 最高位为 1，会被符号扩展为 $-273$（`0xFFFFFEEF`），结果是 `0xDEADAEEF`。正确的做法是把高 20 位加 1：

```asm
lui  a0, 0xDEADC        # a0 = 0xDEADC000
addi a0, a0, -273       # a0 = 0xDEADC000 - 0x111 = 0xDEADBEEF
```

一般地，常数 $c$ 的高 20 位应取 $(c + \mathtt{0x800}) \gg 12$，低 12 位为 $c$ 减去它左移 12 位的结果（在 $[-2048, 2047]$ 中）。伪指令 `li a0, 0xDEADBEEF` 由汇编器自动完成这一计算；常数在 12 位范围内时，`li` 只生成一条 `addi`。在 RV64 中，一个任意的 64 位常数最多需要 8 条指令，编译器常改为从存储器中读出。

**全局变量**的地址也是常数，但要到链接时才知道。汇编代码中用 `%hi(sym)`、`%lo(sym)` 表示地址的高 20 位和低 12 位（含上面的进位修正），由链接器填入。下面是全局数组上的循环（GCC `-O2`，RV32I）：

```c
int fibo[10];
void fib(void) {
    fibo[0] = 1; fibo[1] = 1;
    for (int i = 2; i < 10; i++)
        fibo[i] = fibo[i - 1] + fibo[i - 2];
}
```

```asm
fib:
    lui  a5, %hi(fibo)
    addi a4, a5, %lo(fibo)  # a4 = &fibo[0]
    li   a3, 1
    addi a5, a5, %lo(fibo)  # a5 = &fibo[0], advanced in the loop
    sw   a3, 0(a4)          # fibo[0] = 1
    sw   a3, 4(a4)          # fibo[1] = 1
    addi a2, a5, 32         # a2 = &fibo[8], end of the loop
    li   a4, 1              # a4 = fibo[1]
    j    .L3
.L5:
    lw   a4, 4(a5)          # a4 = p[1]
    lw   a3, 0(a5)          # a3 = p[0]
.L3:
    add  a4, a4, a3
    sw   a4, 8(a5)          # p[2] = p[1] + p[0]
    addi a5, a5, 4          # p++
    bne  a5, a2, .L5
    ret
```

编译器没有逐次计算 `fibo + 4*i`，而是让指针 `a5` 每次加 4，并把循环条件改写为指针比较，省去了乘法和加法。与位置无关的代码改用 `auipc`：`auipc rd, %pcrel_hi(sym)` 算出 `pc` 加上高位偏移，再用 `addi rd, rd, %pcrel_lo(...)` 补上低位，这就是 `la` 的展开方式。全局指针 `gp` 指向静态数据区中间的位置，`gp` 前后各 2 KiB 内的变量可以用一条 `lw t0, off(gp)` 访问，链接器会自动做这种松弛。

## 3.7. 函数调用

### 3.7.1. 调用的步骤

函数（过程）是程序结构化的基本手段（[4.1.4](/4.1.4)）。在机器层面，一次调用要完成六步：

1. 调用者把参数放在被调用函数能取到的地方；
2. 把控制转移到被调用函数（同时保存返回地址）；
3. 被调用函数获取它需要的存储空间（**栈帧**）；
4. 执行函数体；
5. 把返回值放在调用者能取到的地方，释放存储空间；
6. 把控制交还给调用者，回到调用点之后继续执行。

第 2、6 步分别由 `jal ra, f`（或 `call f`）与 `ret` 完成。其余各步怎样做，由软件的约定决定：如果调用者和被调用者对"参数放在哪里""哪些寄存器可以随意使用"理解不同，由不同编译器、不同语言编译的代码就无法互相调用。

### 3.7.2. 调用约定

**定义 3.7.1（调用约定）** 规定函数调用时参数与返回值的传递方式、寄存器在调用前后由谁负责保存、栈的布局与对齐方式的一组软件规则称为**调用约定**（calling convention）。调用约定是应用二进制接口（[4.10.1](/4.10.1#sec-1.3.2)）的一部分。

RISC-V 的调用约定由 RISC-V psABI 规范规定，要点如下：

- 参数：前 8 个整数（或指针）参数依次放在 `a0`–`a7`，浮点参数在硬件浮点的 ABI 中放在 `fa0`–`fa7`；更多的参数放在栈上，第一个栈参数位于函数入口处的 `0(sp)`。宽度为两倍 XLEN 的标量（如 RV32 中的 `long long`）用一对寄存器传递；大于两倍 XLEN 的结构体**按引用传递**（传它的地址）。
- 返回值：放在 `a0`（需要时加上 `a1`），浮点返回值放在 `fa0`（`fa1`）。
- 栈：向低地址生长，`sp` 指向栈顶（最低的已用地址）；函数入口处 `sp` 必须 16 字节对齐。
- 寄存器的保存责任：

**定义 3.7.2（调用者保存寄存器与被调用者保存寄存器）** 被调用函数可以随意改写、调用者若在调用之后还需要其值就必须自己在调用前保存的寄存器称为**调用者保存寄存器**（caller-saved register）；被调用函数若要使用就必须在使用前保存、在返回前恢复，因而在调用前后保持不变的寄存器称为**被调用者保存寄存器**（callee-saved register）。

在 RISC-V 中，`ra`、`t0`–`t6`、`a0`–`a7`（以及 `ft`、`fa` 浮点寄存器）是调用者保存的；`sp`、`s0`–`s11`（以及 `fs0`–`fs11`）是被调用者保存的。`sp` 被调用者保存，是指函数返回时 `sp` 必须恢复为调用时的值，否则调用者就找不到自己的栈帧。把寄存器分成两类是一种折中：调用者保存寄存器适合存放不跨越调用的临时值，被调用者保存寄存器适合存放跨越调用仍需保留的变量，编译器据此分配寄存器，使大多数调用只需保存很少的寄存器。

不同的数据模型对应不同的 ABI 名：`ilp32`（RV32，`int`、`long` 与指针都是 32 位）、`lp64`（RV64，`long` 与指针是 64 位）；后缀 `f`、`d` 表示用浮点寄存器传递单精度或双精度浮点参数，如 Linux 上通用的 `lp64d`。编译时用 `-mabi=` 指定，它必须与 `-march=` 相容。

### 3.7.3. 栈帧

函数需要的存储空间放在**栈帧**中（[4.1.4](/4.1.4#sec-4.4)；程序的内存分区见 [4.1.8](/4.1.8#sec-8.3.1)）：要保存的被调用者保存寄存器、非叶函数的返回地址 `ra`、放不进寄存器的**局部变量**（数组、结构体、取了地址的变量），以及传给下一层函数的多余参数。栈帧的分配与释放就是调整 `sp`，分别在函数的开头和结尾进行：

```asm
func:                          # prologue
    addi sp, sp, -16           # allocate a 16-byte frame
    sw   ra, 12(sp)            # save the return address
    sw   s0, 8(sp)             # save callee-saved registers that will be used
    # ... body: may call other functions ...
    lw   s0, 8(sp)             # epilogue: restore registers
    lw   ra, 12(sp)
    addi sp, sp, 16            # free the frame
    ret
```

开头的这段代码称为序言（prologue），结尾的称为尾声（epilogue）。不调用其他函数的函数称为叶函数，它不必保存 `ra`，若只用临时寄存器和参数寄存器，就完全不需要栈帧。帧指针 `s0`（`fp`）是可选的：使用时它指向函数入口时的 `sp`，局部变量可以用相对于 `fp` 的固定偏移访问，**调试器**也可以沿着帧指针回溯**调用栈**；GCC 在优化时默认不用帧指针，把 `s0` 当作普通的保存寄存器。

调用前后的栈（地址向下递减）：

| 地址 | 内容 |
|---|---|
| 高地址 | 调用者的栈帧 |
| | 第 9 个及以后的参数（如果有） |
| 入口时的 `sp` → | 被调用者的栈帧：保存的 `ra` |
| | 保存的 `s0`、`s1`…… |
| | 局部变量 |
| 当前 `sp` → | 传给下一层的多余参数（如果有） |
| 低地址 | 未用 |

### 3.7.4. 例子

叶函数：参数都在寄存器中，计算后直接返回。

```c
int leaf_example(int g, int h, int i, int j) {
    return (g + h) - (i + j);
}
```

```asm
leaf_example:               # g, h, i, j arrive in a0, a1, a2, a3
    add  a0, a0, a1         # a0 = g + h
    add  a2, a2, a3         # a2 = i + j: argument registers are caller-saved
    sub  a0, a0, a2         # the return value goes in a0
    ret
```

递归函数：`fact` 在调用自己之后还要用到 `n`，所以把 `n` 放进被调用者保存寄存器 `s0`；它改写了 `s0`，又调用了别的函数，因此要在栈帧中保存 `s0` 和 `ra`（GCC `-Og`，RV32IM）。

```c
int fact(int n) {
    if (n < 1) return 1;
    return n * fact(n - 1);
}
```

```asm
fact:
    ble  a0, zero, .L2      # if n < 1, return 1 without a frame
    addi sp, sp, -16        # frame: 16 bytes, keeps sp 16-byte aligned
    sw   ra, 12(sp)         # save the return address
    sw   s0, 8(sp)          # save the caller's s0
    mv   s0, a0             # s0 = n survives the call
    addi a0, a0, -1         # argument n - 1
    call fact               # a0 = fact(n - 1)
    mul  a0, a0, s0         # a0 = n * fact(n - 1)
    lw   ra, 12(sp)         # restore and return
    lw   s0, 8(sp)
    addi sp, sp, 16
    jr   ra
.L2:
    li   a0, 1
    ret
```

每一层递归都压入一个 16 字节的栈帧，`n` 层递归占用 $16n$ 字节的栈；递归过深就会**栈溢出**（[4.1.10](/4.1.10)）。用 `-O2` 编译时，GCC 把这个递归改写成了循环，不再需要栈帧。

## 3.8. 指令编码

### 3.8.1. 六种格式

RISC-V 的基本指令都是 32 位。为了在 32 位中容纳不同用途所需的寄存器字段与立即数，规范定义了六种格式：

| 格式 | 31–25 | 24–20 | 19–15 | 14–12 | 11–7 | 6–0 | 用途 |
|---|---|---|---|---|---|---|---|
| R | `funct7` | `rs2` | `rs1` | `funct3` | `rd` | `opcode` | 寄存器-寄存器运算 |
| I | `imm[11:0]`（12 位，占 31–20） | ← | `rs1` | `funct3` | `rd` | `opcode` | 立即数运算、load、`jalr` |
| S | `imm[11:5]` | `rs2` | `rs1` | `funct3` | `imm[4:0]` | `opcode` | store |
| B | `imm[12,10:5]` | `rs2` | `rs1` | `funct3` | `imm[4:1,11]` | `opcode` | 条件分支 |
| U | `imm[31:12]`（20 位，占 31–12） | ← | ← | ← | `rd` | `opcode` | `lui`、`auipc` |
| J | `imm[20,10:1,11,19:12]`（20 位，占 31–12） | ← | ← | ← | `rd` | `opcode` | `jal` |

（表中 `imm[12,10:5]` 表示这 7 位依次是立即数的第 12 位和第 10–5 位，规范中写作 `imm[12|10:5]`；"←"表示该位段并入左侧的字段。）

这套格式体现了几条设计决策：

1. `opcode` 总在最低 7 位，`rs1`、`rs2`、`rd` 在所有使用它们的格式中位置相同。处理器在译码完成之前就可以按固定的位段读寄存器堆；读出的值若用不到，丢掉即可。寄存器读出处在处理器的关键路径上，这一点对时钟周期很重要（[4.10.6](/4.10.6)）。
2. 立即数的符号位总是指令的第 31 位，符号扩展可以与译码并行进行。
3. 宁可把立即数的位打乱，也要让各格式中同一个立即数位尽量落在指令的同一位置，以减少拼接立即数时所需的**数据选择器**（3.8.5 节）。S 型把立即数拆成两段，就是为了不移动 `rs2` 和 `rd` 的位置。
4. **操作码**字段按功能分组：`opcode` 决定格式和大类，`funct3`、`funct7` 进一步区分具体操作，相当于一种扩展操作码（[4.10.2](/4.10.2#sec-2.2.2)）。

### 3.8.2. R 型与 I 型

R 型指令的 `opcode` 都是 `0110011`（OP），具体操作由 `funct3` 与 `funct7` 决定。例如 `add x8, x9, x10`：

| 字段 | `funct7` | `rs2` | `rs1` | `funct3` | `rd` | `opcode` |
|---|---|---|---|---|---|---|
| 十进制 | 0 | 10 | 9 | 0 | 8 | 51 |
| 二进制 | `0000000` | `01010` | `01001` | `000` | `01000` | `0110011` |

机器码为 `0000 0000 1010 0100 1000 0100 0011 0011`，即十六进制 `0x00A48433`。`sub` 与 `add` 只差 `funct7` 的第 30 位（`0100000`），`sra` 与 `srl` 也是如此；硬件可以直接用这一位控制加法器做减法，或控制移位器补符号位。M 扩展的乘除法指令也是 R 型，`funct7 = 0000001`。

I 型把 R 型的 `funct7` 与 `rs2` 两个字段合并为 12 位立即数，其余字段不变。例如 `addi x15, x1, -50`：$-50$ 的 12 位补码是 `111111001110`，

| 字段 | `imm[11:0]` | `rs1` | `funct3` | `rd` | `opcode` |
|---|---|---|---|---|---|
| 值 | $-50$ | 1 | 0 | 15 | `0x13` |
| 二进制 | `111111001110` | `00001` | `000` | `01111` | `0010011` |

机器码为 `0xFCE08793`。load 指令也是 I 型（`opcode = 0000011`），`lw x14, 8(x2)` 中 `rs1 = 2` 是基址寄存器，`rd = 14`，立即数 8 是位移量，`funct3 = 010` 表示字，机器码 `0x00812703`。移位立即数指令只需 5 位（RV64 为 6 位）`shamt`，立即数的高位用作类似 `funct7` 的字段区分逻辑右移和算术右移：`srai x5, x6, 3` 是 `0x40335293`。`jalr` 也是 I 型（`opcode = 1100111`）。

### 3.8.3. S 型与 B 型

store 指令需要两个源寄存器（基址 `rs1` 与数据 `rs2`）和 12 位位移量，没有 `rd`。为了让 `rs2` 留在与 R 型相同的位置，立即数被拆成两段：高 7 位放在 31–25 位，低 5 位放在原来 `rd` 的位置。例如 `sw x14, 8(x2)`：

| 字段 | `imm[11:5]` | `rs2` | `rs1` | `funct3` | `imm[4:0]` | `opcode` |
|---|---|---|---|---|---|---|
| 值 | 0 | 14 | 2 | 2（字） | 8 | `0x23` |
| 二进制 | `0000000` | `01110` | `00010` | `010` | `01000` | `0100011` |

机器码为 `0x00E12423`。

条件分支也需要两个源寄存器和一个立即数，格式与 S 型相同，区别在于立即数的含义：它是以字节为单位、相对于本条指令地址的转移偏移量，并且总是偶数（有 C 扩展时指令按 2 字节对齐），最低位不必存储。于是 12 位立即数字段表示的是 13 位偏移量 `imm[12:1]`，范围是 $[-4096, 4094]$ 字节，即当前指令前后约 4 KiB：

$$
\text{转移目标} = \mathrm{pc} + \operatorname{sext}(\mathrm{imm}[12:1] \,\|\, 0).
$$

B 型立即数的位排列 `imm[12,10:5]` 与 `imm[4:1,11]` 看起来古怪，原因是要与 S 型尽量对齐：`imm[10:5]` 和 `imm[4:1]` 与 S 型中对应位的位置相同，只有 S 型中最低位的位置（第 7 位）在 B 型中改放 `imm[11]`，而符号位 `imm[12]` 放在第 31 位。`opcode` 都是 `1100011`（BRANCH），六种分支由 `funct3` 区分（`beq` 为 `000`，`bne` 为 `001`，`blt`、`bge`、`bltu`、`bgeu` 依次为 `100`–`111`）。

**例 3.8.1** 对下面的循环编码第一条指令：

```asm
Loop: beq  x9, x0, End      # address L
      add  x8, x8, x10      # L + 4
      addi x9, x9, -1       # L + 8
      j    Loop             # L + 12
End:  ...                   # L + 16
```

`End` 比 `beq` 的地址大 16，偏移量 $16 = (0\,0000\,0001\,0000)_2$，于是 `imm[12] = 0`、`imm[10:5] = 000000`、`imm[4:1] = 1000`、`imm[11] = 0`：

| 字段 | `imm[12,10:5]` | `rs2` | `rs1` | `funct3` | `imm[4:1,11]` | `opcode` |
|---|---|---|---|---|---|---|
| 二进制 | `0000000` | `00000` | `01001` | `000` | `10000` | `1100011` |

机器码为 `0x00048863`。最后的 `j Loop` 即 `jal x0, -12`，编码为 `0xFF5FF06F`。

**PC 相对寻址**的好处是：整段代码移动到别的地址时，其中的分支编码不必修改；只移动其中几条指令时，跨越移动部分的偏移量才需要重算。

### 3.8.4. U 型与 J 型

U 型有一个 20 位立即数字段，放在指令的高 20 位。`lui rd, imm` 把它放到 `rd` 的高 20 位、低 12 位清零；`auipc rd, imm` 把同样构成的数加到本条指令的地址上。例如 `lui x10, 0xDEADC` 编码为 `0xDEADC537`。它们与 12 位立即数的指令组合，就能构成任意 32 位的常数和地址（3.6.2 节）。

J 型只用于 `jal`。它的 20 位立即数字段表示 21 位的偶数偏移量 `imm[20:1]`，范围为 $[-2^{20}, 2^{20} - 2]$ 字节，即前后约 1 MiB。其位排列 `imm[20,10:1,11,19:12]` 同样是为了与 I 型、U 型对齐：`imm[10:1]` 在 I 型中对应位的位置，`imm[19:12]` 在 U 型中对应位的位置。`jalr` 是 I 型，它的 12 位立即数直接加到 `rs1` 上，不隐含末位的 0。

### 3.8.5. 立即数的拼接

处理器译码时要从指令中拼出一个 32 位、符号扩展过的立即数，这由一个组合电路完成，[4.10.6](/4.10.6) 的数据通路中称为立即数生成器。下表给出各格式的 32 位立即数的每一段来自指令的哪些位（`inst[31]` 重复填满高位就是符号扩展）：

| 格式 | 立即数 31–20 | 19–12 | 11 | 10–5 | 4–1 | 0 |
|---|---|---|---|---|---|---|
| I | `inst[31]` | `inst[31]` | `inst[31]` | `inst[30:25]` | `inst[24:21]` | `inst[20]` |
| S | `inst[31]` | `inst[31]` | `inst[31]` | `inst[30:25]` | `inst[11:8]` | `inst[7]` |
| B | `inst[31]` | `inst[31]` | `inst[7]` | `inst[30:25]` | `inst[11:8]` | 0 |
| U | `inst[31:20]` | `inst[19:12]` | 0 | 0 | 0 | 0 |
| J | `inst[31]` | `inst[19:12]` | `inst[20]` | `inst[30:25]` | `inst[24:21]` | 0 |

可以看到对齐的效果：符号位在所有格式中都来自 `inst[31]`；立即数的第 10–5 位在 I、S、B、J 型中都来自 `inst[30:25]`；第 4–1 位只有两个来源。每一段立即数只需在两三个来源中选择，选择器小而快。

### 3.8.6. RV32I 指令一览

RV32I 共 40 条指令。下表按 `opcode` 分组列出，`funct3`、`funct7` 用二进制表示：

| `opcode` | 格式 | 指令（`funct3`；需要时加 `funct7`） |
|---|---|---|
| `0110111` LUI | U | `lui` |
| `0010111` AUIPC | U | `auipc` |
| `1101111` JAL | J | `jal` |
| `1100111` JALR | I | `jalr`（000） |
| `1100011` BRANCH | B | `beq`（000）、`bne`（001）、`blt`（100）、`bge`（101）、`bltu`（110）、`bgeu`（111） |
| `0000011` LOAD | I | `lb`（000）、`lh`（001）、`lw`（010）、`lbu`（100）、`lhu`（101） |
| `0100011` STORE | S | `sb`（000）、`sh`（001）、`sw`（010） |
| `0010011` OP-IMM | I | `addi`（000）、`slti`（010）、`sltiu`（011）、`xori`（100）、`ori`（110）、`andi`（111）、`slli`（001；0000000）、`srli`（101；0000000）、`srai`（101；0100000） |
| `0110011` OP | R | `add`（000；0000000）、`sub`（000；0100000）、`sll`（001）、`slt`（010）、`sltu`（011）、`xor`（100）、`srl`（101；0000000）、`sra`（101；0100000）、`or`（110）、`and`（111） |
| `0001111` MISC-MEM | I | `fence`（000） |
| `1110011` SYSTEM | I | `ecall`（立即数 0）、`ebreak`（立即数 1） |

R 型中未注明 `funct7` 的为 `0000000`。M 扩展的八条指令使用 OP 的 `opcode`、`funct7 = 0000001`，`funct3` 依次为 `mul`（000）、`mulh`（001）、`mulhsu`（010）、`mulhu`（011）、`div`（100）、`divu`（101）、`rem`（110）、`remu`（111）。Zicsr 的 `csrrw` 等指令也使用 SYSTEM 的 `opcode`。RV64I 另有 OP-IMM-32（`0011011`）与 OP-32（`0111011`）两组，用于 `addiw`、`addw` 等字运算。

`fence` 用于多处理器和设备访问的存储器访问排序，`ecall` 用于系统调用，`ebreak` 把控制交给**调试器**。一个简单的实现可以把 `fence` 当作空操作，把 `ecall` 和 `ebreak` 实现为总是陷入异常。

### 3.8.7. 用 Python 编码指令

按 3.8.1 节的格式表，编码就是把各字段移位后按位或起来。下面的函数实现了六种格式，并用前面几节的例子检验（结果与 GNU 汇编器的输出一致）：

```python
def bits(x, hi, lo):
    """Return bits hi..lo of x (two's complement for negative x)."""
    return (x >> lo) & ((1 << (hi - lo + 1)) - 1)

def r_type(funct7, rs2, rs1, funct3, rd, opcode):
    return funct7 << 25 | rs2 << 20 | rs1 << 15 | funct3 << 12 | rd << 7 | opcode

def i_type(imm, rs1, funct3, rd, opcode):
    assert -2048 <= imm < 2048
    return bits(imm, 11, 0) << 20 | rs1 << 15 | funct3 << 12 | rd << 7 | opcode

def s_type(imm, rs2, rs1, funct3, opcode):
    assert -2048 <= imm < 2048
    return (bits(imm, 11, 5) << 25 | rs2 << 20 | rs1 << 15 | funct3 << 12
            | bits(imm, 4, 0) << 7 | opcode)

def b_type(imm, rs2, rs1, funct3, opcode=0b1100011):
    assert -4096 <= imm < 4096 and imm % 2 == 0
    return (bits(imm, 12, 12) << 31 | bits(imm, 10, 5) << 25 | rs2 << 20
            | rs1 << 15 | funct3 << 12 | bits(imm, 4, 1) << 8
            | bits(imm, 11, 11) << 7 | opcode)

def u_type(imm20, rd, opcode):
    return bits(imm20, 19, 0) << 12 | rd << 7 | opcode

def j_type(imm, rd, opcode=0b1101111):
    assert -(1 << 20) <= imm < (1 << 20) and imm % 2 == 0
    return (bits(imm, 20, 20) << 31 | bits(imm, 10, 1) << 21
            | bits(imm, 11, 11) << 20 | bits(imm, 19, 12) << 12 | rd << 7 | opcode)

tests = {
    "add x8, x9, x10":   r_type(0b0000000, 10, 9, 0b000, 8, 0b0110011),
    "addi x15, x1, -50": i_type(-50, 1, 0b000, 15, 0b0010011),
    "sw x14, 8(x2)":     s_type(8, 14, 2, 0b010, 0b0100011),
    "beq x9, x0, +16":   b_type(16, 0, 9, 0b000),
    "jal x0, -12":       j_type(-12, 0),
    "lui x10, 0xDEADC":  u_type(0xDEADC, 10, 0b0110111),
}
for asm, word in tests.items():
    print(f"{asm:20s} 0x{word:08x}")
```

```text
add x8, x9, x10      0x00a48433
addi x15, x1, -50    0xfce08793
sw x14, 8(x2)        0x00e12423
beq x9, x0, +16      0x00048863
jal x0, -12          0xff5ff06f
lui x10, 0xDEADC     0xdeadc537
```

### 3.8.8. 压缩指令

C 扩展为最常用的指令提供 16 位编码，如 `c.addi`、`c.lw`、`c.mv`、`c.j`。它们的字段更短：多数只能访问 8 个最常用的寄存器（`x8`–`x15`，即 `s0`、`s1`、`a0`–`a5`），立即数更小，有的要求目的寄存器与一个源寄存器相同。每条压缩指令都对应一条 32 位指令，所以 C 扩展只影响代码密度，不增加新的功能，处理器可以在译码时先把它展开成 32 位指令。

16 位与 32 位指令可以任意混合，靠最低两位区分：32 位指令的最低两位是 `11`，压缩指令是 `00`、`01` 或 `10`。这样，**译码器**看前两位就知道指令的长度，指令长度的编码构成一个**前缀码**（[4.10.2](/4.10.2#sec-2.2.2)），规范也为将来更长的指令保留了编码空间。程序中 50%–60% 的指令可以压缩，代码量因此减少约 25%–30%，这对指令高速缓存和嵌入式系统的存储容量都有意义。代价是指令只能按 2 字节对齐，32 位指令可能跨越高速缓存行，取指单元更复杂。这也是分支与 `jal` 的偏移量以 2 字节为单位的原因。

## 小结

- RISC-V 是开放、模块化的 RISC 指令集：基本指令集 RV32I / RV64I 加上 M、A、F、D、C、V 等可选扩展；特权规范定义 M、S、U 三种模式和 CSR。
- 寄存器堆有 32 个通用寄存器，`x0` 恒为 0；ABI 名规定了参数（`a0`–`a7`）、返回地址（`ra`）、栈指针（`sp`）、临时寄存器（`t`）与保存寄存器（`s`）的用途。
- 运算指令只在寄存器之间进行，不检测溢出，没有条件码；有符号与无符号的区别只出现在比较、分支与 load 的扩展方式中。乘除法由 M 扩展提供，除以零不产生异常。
- 存储器按字节寻址，RISC-V 是小端序；load / store 用**基址寻址**，`lb`/`lbu` 等决定符号扩展或零扩展。数据应当对齐。
- 条件分支比较两个寄存器并做 PC 相对转移（±4 KiB）；`jal`（±1 MiB）与 `jalr` 实现跳转、调用与返回。伪指令由汇编器翻译为真实指令；32 位常数与地址用 `lui`/`auipc` 加 `addi` 构成。
- 调用约定规定参数、返回值、栈的对齐，以及调用者保存（`t`、`a`、`ra`）与被调用者保存（`s`、`sp`）寄存器；函数用序言和尾声分配和释放栈帧。
- 六种 32 位指令格式 R、I、S、B、U、J 保持寄存器字段位置固定、符号位总在第 31 位，立即数的位为此被重新排列；C 扩展的 16 位指令以最低两位区分长度。
