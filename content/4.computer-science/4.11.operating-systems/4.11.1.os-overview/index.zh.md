计算机上的每个程序都运行在操作系统之上。程序看到的是独占的处理器、一大块私有的内存、重启后仍然存在的文件，以及能投递消息的网络；而硬件提供的只是几个核、由所有程序共享的有限物理内存、按编号读写块的存储设备，以及搬运帧的网卡。操作系统用后者构造出前者，在众多程序与用户之间分配硬件，并防止它们相互干扰。本章讨论操作系统是什么、为什么成了今天的样子，以及这一切所依赖的硬件机制：处理器有两种特权模式，程序只能通过明确定义的入口，即系统调用，进入操作系统。后续各章依次讨论三大主题：处理器的虚拟化（[4.11.2](/4.11.2)、[4.11.3](/4.11.3)）与内存的虚拟化（[4.11.4](/4.11.4)、[4.11.5](/4.11.5)）、并发（[4.11.6](/4.11.6)）、持久性（[4.11.7](/4.11.7)、[4.11.8](/4.11.8)）；最后三章转向虚拟机与容器，以及 Linux 在工作站、服务器和集群上的实际使用。硬件一侧（指令系统、RISC-V 的特权模式、处理器）是 [4.10](/4.10) 的内容；这里取程序员和系统设计者的视角，以 x86-64 上的 Linux 为主要例子。

## 1.1. 操作系统的作用

### 1.1.1. 定义与角色

**定义 1.1.1（操作系统）** **操作系统**（OS）是管理计算机硬件资源（处理器、内存、存储和其他设备），并通过固定的接口向程序提供这些资源的抽象的软件。其中以完全的硬件特权运行、常驻内存的部分是**内核**；其余部分（Shell、系统库、服务程序）作为普通程序运行。

操作系统同时扮演三个角色：

- 魔术师：把有限的物理资源变成更易使用、看上去不受限制或为程序独占的抽象。一个处理器变成许多进程，几 GB 的内存变成每个程序私有的地址空间，由编号块组成的磁盘变成带名字的文件树。
- 裁判：决定谁在何时得到哪种资源（调度、内存分配、磁盘配额），并把程序与用户相互隔离，使出错或恶意的程序不能读取别人的内存，也不能使整台机器崩溃。
- 胶水：提供每个程序都需要的公共服务（文件系统、网络、时钟、终端），使应用程序不必自己驱动每一种设备。

标准教材的组织方式（Arpaci-Dusseau，《操作系统导论》）把工作分为三个主题，本课程也按此展开：

| 主题 | 问题 | 物理资源 → 抽象 | 章节 |
|---|---|---|---|
| 虚拟化 | 一台机器怎样看起来像许多台？ | CPU → 进程与线程；内存 → 地址空间 | 4.11.2–4.11.5 |
| 并发 | 共享数据的多个活动怎样同时正确地运行？ | 锁、条件变量、信号量 | 4.11.6 |
| 持久性 | 数据怎样在崩溃和断电后保存下来？ | 磁盘与固态硬盘 → 文件与目录 | 4.11.7–4.11.8 |

安全性贯穿这三者：进程之间的隔离、文件的权限，以及用户程序与内核之间的边界。

### 1.1.2. 设计目标

操作系统的设计是几个目标之间的权衡：

- 抽象：程序应当针对简单而稳定的接口（文件、进程）编写，而不是针对具体的硬件。
- 性能：操作系统本身是开销。它的机制只能耗费很少的时间（一次系统调用约一百纳秒，见 1.4.3 节）和很少的空间。
- 保护与隔离：一个程序的错误不能影响另一个程序；内核不能信任来自用户程序的任何输入。
- 可靠性：内核一直在运行，其中的一个错误就会使整台机器宕机。
- 能耗、安全性和可移植性的重要程度随平台（手机、笔记本电脑、集群节点）而不同。

一个反复出现的设计原则是机制与策略分离（separation of mechanism and policy）：内核实现底层的机制（怎样从一个进程切换到另一个进程，怎样映射一个页），而使用该机制的策略（下一个运行哪个进程，淘汰哪一页）则与之分开，并且可以替换。[4.11.3](/4.11.3) 中的调度策略和 [4.11.4](/4.11.4) 中的页面置换策略是主要的例子。

## 1.2. 简史

操作系统起源于让昂贵的机器保持忙碌的努力，后来又出于舒适地共享机器的愿望而发展。

| 时期 | 发展 | 引入的思想 |
|---|---|---|
| 1950 年代 | 批处理系统（如用于 IBM 704 的 GM-NAA I/O）：操作员送入一个作业队列，常驻的监控程序依次加载每个作业 | 设备例程库；第一个"操作系统"就是作业加载器 |
| 1960 年代 | 多道程序设计（multiprogramming）：多个作业同时驻留内存，运行中的作业等待 I/O 时 CPU 切换到另一个作业（IBM OS/360） | 计算与 I/O 重叠；需要内存保护 |
| 1960 年代 | 分时（time-sharing）：许多交互式用户共享一台机器，每人得到很短的时间片（1961 年麻省理工学院的 CTSS、1969 年的 Multics） | 交互式响应；层次式文件系统；保护环 |
| 1969–1980 年代 | Unix（Thompson 与 Ritchie，贝尔实验室，1973 年用 C 重写）；伯克利的 BSD 加入了虚拟内存与网络（TCP/IP 套接字） | 小而可组合的程序、"一切皆文件"、管道、用**高级语言**编写的可移植内核 |
| 1980 年代 | 没有保护机制的个人计算机（MS-DOS、早期 Mac OS）；POSIX（IEEE 1003.1，1988 年）把 Unix 接口标准化 | 类 Unix 系统共同的 API |
| 1991 年起 | Linux（Linus Torvalds），与 GNU 用户空间工具结合；Windows NT（1993 年）；基于 Darwin/XNU 内核的 macOS（2001 年） | 自由软件内核；至今仍占主导的操作系统 |
| 2000 年代起 | 通用硬件上的虚拟机、智能手机（iOS；基于 Linux 内核的 Android）、云计算、容器 | 运行在其他操作系统之上的操作系统（[4.11.9](/4.11.9)） |

如今几乎所有计算机都运行三个内核家族之一。Linux 内核运行着 Android 手机、大多数服务器与云实例、嵌入式设备，并且自 2017 年 11 月起，TOP500 榜单上最快的 500 台超级计算机全部运行 Linux。Windows 在桌面计算机上占主导，苹果的 XNU 内核运行 macOS 和 iOS。macOS 是经过认证的 Unix（符合 POSIX 标准），Linux 是类 Unix 系统；Windows 有自己的接口（Win32 API），并通过 WSL 运行 Linux 程序（1.5.4 节）。

## 1.3. 内核态与用户态

### 1.3.1. 特权模式

如果每个程序都能执行每条指令，任何程序就都能覆盖内核、重新设置磁盘控制器或关闭定时器，隔离也就无从谈起。解决办法在硬件中。

**定义 1.3.1（用户态与内核态）** 支持操作系统的处理器至少有两个特权级。在**内核态**（管态，supervisor mode）下，代码可以执行所有指令，访问所有内存和设备。在**用户态**下，特权指令（privileged instruction），如修改页表、关中断、直接访问 I/O 设备、停止处理器，被禁止，内存访问也被限制在内核所允许的范围内；违反这些规则会引发异常，使控制权转移给内核。

内核运行在内核态，每个应用程序运行在用户态。每种**指令集体系结构**对这些特权级各有称呼：

| 体系结构 | 特权级（由低到高） | Linux 使用 |
|---|---|---|
| x86-64 | 环 3、2、1、0（环 1 和 2 现已不用） | 用户程序用环 3，内核用环 0 |
| ARMv8 / ARMv9 | EL0、EL1、EL2（虚拟机监控器）、EL3（安全监控器） | EL0 和 EL1 |
| **RISC-V** | U、S、M（机器模式，固件）；用于虚拟机监控器的 H 扩展（[4.10.3](/4.10.3)） | U 和 S |

模式切换只发生在两个方向上。用户代码不能直接跳进内核态：它只能通过异常进入内核，入口地址是内核在启动时存入受保护表中的。内核用一条特殊指令（x86-64 上是 `sysret` 或 `iret`，RISC-V 上是 `sret`）返回用户态，这条指令一步完成降低特权级和跳转回去。

### 1.3.2. 异常、中断与陷阱

程序通常一条接一条地执行指令，跳转和调用以程序自己选择的方式改变执行顺序。异常控制流（exceptional control flow）是由程序没有以跳转形式表达的事件所引起的控制流变化：一次按键、定时器到期、除以零、对内核的一次请求。内核正是通过它获得控制权。

**定义 1.3.2（异常）** **异常**是为响应某个事件而从运行中的程序到内核的突然的控制转移，该事件或者由正在执行的指令引起，或者来自外部设备。处理器保存足以恢复该程序的状态（至少是程序计数器和处理器状态），切换到内核态，并跳转到异常处理程序（exception handler）；处理程序的地址取自异常表（exception table），在 x86-64 上是中断描述符表，，以异常号为下标。

依照 Bryant 与 O'Hallaron（《深入理解计算机系统》），异常分为四类。

**定义 1.3.3（中断、陷阱、故障、终止）** **中断**是由处理器之外的设备（定时器、网卡、表示完成的磁盘控制器）异步引起的异常；处理完毕后，处理器在下一条指令处恢复被中断的程序。**陷阱**是执行特殊指令而有意引起的异常，主要用于向内核请求服务；控制返回到下一条指令。**故障**由内核可能修复的指令引起（缺页，[4.11.4](/4.11.4)）；若处理程序排除了原因，出错的指令会被重新执行，否则程序被终止。**终止**是不可恢复的硬件错误（例如无法纠正的内存错误）；程序或整台机器被停止。

| 类别 | 原因 | 同步？ | 返回到 |
|---|---|---|---|
| 中断 | 来自 I/O 设备或定时器的信号 | 否 | 下一条指令 |
| 陷阱 | 有意为之（`syscall`、`ecall`、`int3`） | 是 | 下一条指令 |
| 故障 | 可能恢复的错误（缺页、除以零、保护违例） | 是 | 同一条指令，或不返回 |
| 终止 | 不可恢复的硬件错误 | 是 | 不返回 |

术语并不统一：Intel 和 RISC-V 把四类都叫"异常"或"陷阱"（RISC-V 用"陷阱"指控制权的转移，用"异常"指同步原因，用"中断"指异步原因），许多教材则用"中断"泛指全部。行为在各处都是一样的。有两点后果对以后的一切都很重要。第一，定时器中断保证内核即使在程序陷入死循环时也能周期性地重新获得控制权；内核正是这样在许多进程之间共享一个处理器的（[4.11.2](/4.11.2)）。第二，故障使内核能够在内存尚未就绪时让它看起来已经就绪：第一次访问尚不在内存中的页会引发故障，内核装入该页，指令被重试，程序对此毫无察觉（[4.11.4](/4.11.4)）。

### 1.3.3. 内核体系结构

操作系统有多少部分运行在内核态，是一种设计选择。

- 宏内核（monolithic kernel）把调度器、内存管理、文件系统、网络协议栈和设备驱动都放在内核态，在同一个地址空间中运行。子系统之间的调用就是普通的函数调用，速度快；但任何一个驱动中的错误都可能使整个系统崩溃。Linux 和 BSD 是宏内核；Linux 用可加载内核模块（运行时加载的驱动，`lsmod`、`modprobe`）和 eBPF 来减轻其僵化：eBPF 使经过验证的用户提供的程序能在内核中安全运行，用于跟踪、网络，自 Linux 6.12 起还用于调度。
- 微内核（microkernel）在内核态只保留最少的部分（地址空间、线程、进程间通信），而把文件系统、驱动和网络协议栈作为用户态的服务器进程运行，彼此通过消息通信（Mach、QNX，以及经过形式化验证的 seL4）。故障被限制在局部，但每次服务请求都要付出额外的模式切换和消息的代价。
- 混合内核（Windows NT、苹果的 XNU）从微内核设计出发，又把对性能要求高的服务移回内核态。

## 1.4. 系统调用

### 1.4.1. 系统调用接口

**定义 1.4.1（系统调用）** **系统调用**是用户程序向内核提出的、对需要内核特权的服务（如读文件、创建进程或分配内存）的请求。它通过执行陷阱指令发出，所请求服务的编号和参数放在约定的寄存器中；内核检查参数，在内核态完成服务，并把结果返回给程序。

系统调用接口是内核的边界：它是程序影响自身内存以外任何事物的唯一途径。Linux 上有大约 350–460 个系统调用，数目随体系结构而异。它们分为以下几类：

| 类别 | 例子 |
|---|---|
| 进程 | `fork`/`clone`、`execve`、`exit`、`wait4`、`kill`、`getpid` |
| 内存 | `mmap`、`munmap`、`brk`、`mprotect` |
| 文件与目录 | `openat`、`read`、`write`、`close`、`lseek`、`stat`、`mkdir`、`unlink`、`rename` |
| 设备与 I/O | `ioctl`、`poll`、`epoll_wait`、`io_uring_enter` |
| 通信 | `pipe`、`socket`、`connect`、`sendmsg` |
| 时间与信息 | `clock_gettime`、`nanosleep`、`uname` |

程序很少自己执行陷阱指令。C 库（大多数 Linux 发行版用 glibc，Alpine 用 musl）为每个系统调用提供一个包装函数，它把参数放入寄存器，执行陷阱，并转换结果：按约定，内核在失败时返回负的错误号 $-e$，包装函数把 $e$ 存入变量 `errno` 并返回 $-1$。手册页区分这两层：第 2 节记录系统调用（`man 2 write`），第 3 节记录库函数（`man 3 printf`）；`printf` 是库函数，它先格式化到缓冲区，最终调用 `write`。

### 1.4.2. x86-64 Linux 上的机制

在 x86-64 上，Linux 把系统调用号放在寄存器 `rax` 中，最多六个参数依次放在 `rdi`、`rsi`、`rdx`、`r10`、`r8` 和 `r9` 中；`syscall` 指令切换到内核态，并跳转到内核在启动时登记的入口；结果从 `rax` 返回。这与 x86-64 Linux 的函数**调用约定**（RISC-V 的调用约定见 [4.10.3](/4.10.3)）只有第四个参数不同：函数用 `rcx` 接收第四个参数，而 `syscall` 指令本身会覆盖 `rcx`（写入返回地址）和 `r11`（写入标志寄存器）。下面的程序绕过 C 库，直接调用 `write`（编号 1）：

```c
#include <stdio.h>

/* Invoke write(2) directly with the x86-64 syscall instruction. */
static long raw_write(long fd, const void *buf, unsigned long n) {
    long ret;
    __asm__ volatile ("syscall"
                      : "=a"(ret)                     /* rax: return value */
                      : "a"(1L),                      /* rax: number of write */
                        "D"(fd), "S"(buf), "d"(n)     /* rdi, rsi, rdx: arguments */
                      : "rcx", "r11", "memory");      /* clobbered by syscall */
    return ret;
}

int main(void) {
    long ok = raw_write(1, "hello from the kernel\n", 22);
    long bad = raw_write(42, "x", 1);                 /* no such descriptor */
    printf("returned %ld and %ld\n", ok, bad);
    return 0;
}
```

```text
hello from the kernel
returned 22 and -9
```

第一次调用向文件描述符 1（标准输出）写入了 22 字节。第二次使用了一个未打开的描述符，内核返回 $-9$，即 $-$`EBADF`（"错误的文件描述符"）；通过库包装函数，同样的调用返回 $-1$，`perror` 打印 `Bad file descriptor`。在内核一侧，入口代码把用户寄存器保存到每个线程各自的内核栈上，按编号在系统调用表中查找处理函数，并检查每一个参数：用户传入的指针必须指向用户自己的内存，否则调用以 `EFAULT` 失败。内核从不信任用户内存，因为同一程序的另一个线程可能在调用期间修改它。

命令 `strace ./program`（大多数发行版需要另外安装）显示程序发出的每个系统调用及其参数和结果。要看清程序实际做了什么，这是最快的办法：它打开了哪些文件，在哪里失败，在哪里等待。

### 1.4.3. 系统调用的开销

系统调用比函数调用昂贵得多：要做模式切换、保存和恢复寄存器、检查参数；在易受 Meltdown 和 Spectre 攻击（2018 年）影响的处理器上，还要在内核边界上增加缓解措施。下面是在本课程自始至终使用的笔记本电脑（Intel Core Ultra 7 258V，WSL 2 下的 Linux 6.6）上的测量，对 $10^7$ 次调用取平均：

```c
#define _GNU_SOURCE
#include <stdio.h>
#include <time.h>
#include <unistd.h>
#include <sys/syscall.h>

static double now(void) {
    struct timespec t;
    clock_gettime(CLOCK_MONOTONIC, &t);
    return t.tv_sec + t.tv_nsec * 1e-9;
}

static int f(int x) { return x + 1; }
int (*volatile fp)(int) = f;   /* defeat inlining */

int main(void) {
    const int N = 10000000;
    double t0 = now();
    int s = 0;
    for (int i = 0; i < N; i++) s = fp(s);
    double t1 = now();
    for (int i = 0; i < N; i++) syscall(SYS_getppid);
    double t2 = now();
    struct timespec ts;
    for (int i = 0; i < N; i++) clock_gettime(CLOCK_MONOTONIC, &ts);
    double t3 = now();
    printf("function call      %6.1f ns\n", (t1 - t0) / N * 1e9);
    printf("getppid() syscall  %6.1f ns\n", (t2 - t1) / N * 1e9);
    printf("clock_gettime vDSO %6.1f ns\n", (t3 - t2) / N * 1e9);
    return s == 0;
}
```

```text
function call         2.4 ns
getppid() syscall   220.9 ns
clock_gettime vDSO   49.7 ns
```

最简单的系统调用 `getppid` 的开销约为函数调用的一百倍（裸机 Linux 上通常为 50–150 ns；WSL 的虚拟机还会增加一些）。由此得到两点：

- 程序把请求成批处理。C 库的 `stdio` 对输出做缓冲，每积累几 KB 才调用一次 `write`，而不是每个字符调用一次；以大块读取文件也比逐字节读取快得多（[4.11.8](/4.11.8)）。
- 频繁的只读调用不进入内核就能完成。内核向每个进程映射一个很小的**共享库**，即 vDSO（virtual dynamic shared object）；`clock_gettime` 和 `gettimeofday` 从内核持续更新的一个页面中读取时间，不需要模式切换。

## 1.5. Linux 与 WSL

### 1.5.1. Linux 内核

Linux 是自由的、宏内核的、类 Unix 的内核，由 Linus Torvalds 于 1991 年开始编写，此后由数千名贡献者在 GNU 通用公共许可证第 2 版下开发。每九到十周发布一个新的主线版本；每年有一个版本成为长期支持（LTS）版并维护数年，各发行版即以这些版本为基础。版本号由 `uname -r` 打印：

```text
$ uname -r
6.6.114.1-microsoft-standard-WSL2
```

这是 Microsoft 为 WSL 2 构建的 LTS 内核 6.6（2023 年 10 月发布）。内核的大部分是设备驱动；核心子系统有进程调度器（[4.11.3](/4.11.3)）、内存管理（[4.11.4](/4.11.4)）、虚拟文件系统层及其下具体的文件系统（[4.11.7](/4.11.7)）、块层与网络层，以及使容器成为可能的命名空间和 cgroup 等安全机制（[4.11.9](/4.11.9)）。

内核把它的许多状态呈现为文件。伪文件系统 `/proc` 为每个进程设有一个目录（`/proc/<pid>/status`、`/proc/<pid>/maps`），并有系统范围的文件（`/proc/cpuinfo`、`/proc/meminfo`、`/proc/loadavg`）；`/sys` 描述设备和内核参数。`ps`、`top`、`free` 等工具只是读取这些文件的前端。

### 1.5.2. 发行版

单有内核还不是可用的系统。Linux 发行版（Linux distribution）把内核与 C 库、GNU 核心工具和 Shell、初始化系统、**包管理器**以及数千个应用程序组合在一起，并经过共同的构建和测试。

| 家族 | 发行版 | 包管理器 | 典型用途 |
|---|---|---|---|
| Debian | Debian、Ubuntu（每两年一个 LTS 版） | `apt`（`.deb`） | 桌面、WSL 默认、许多服务器和云镜像 |
| Red Hat | RHEL、Rocky Linux、AlmaLinux、Fedora | `dnf`（`.rpm`） | 企业服务器、大多数 HPC 集群 |
| 其他 | Arch Linux、openSUSE、Alpine（musl，非常小，常见于容器） | `pacman`、`zypper`、`apk` | 爱好者、容器 |

科学软件主要为 Linux 发布：集群上的编译器、MPI 库和作业调度器只支持 Linux，生物信息学工具首先在 Linux 上开发并为之打包（Bioconda 为每个包构建 Linux 版，而 macOS 版只有一部分）。conda 及其更快的重新实现等在用户空间工作的包管理器绕开了发行版自带的包（[4.11.11](/4.11.11)）。

### 1.5.3. 从加电到登录提示符

现代 PC 或服务器的启动过程展现了系统的各个层次：

```mermaid
flowchart LR
  A["固件 (UEFI)"] --> B["引导加载程序 (GRUB, systemd-boot)"]
  B --> C["内核 + initramfs"]
  C --> D["init: systemd (PID 1)"]
  D --> E["服务、登录、Shell"]
```

固件初始化硬件，并从 EFI 系统分区加载引导加载程序；引导加载程序加载压缩的内核映像和初始内存文件系统（initramfs），后者包含寻找真正的根文件系统所需的驱动；内核初始化内存管理、调度器和驱动，挂载根文件系统，并启动第一个用户进程 `init`，其**进程标识符**为 1。在几乎所有现行发行版上，`init` 都是 systemd，它按依赖关系并行启动各项服务并监督它们（`systemctl status`、`journalctl`）。其余每个进程都是它的后代（[4.11.2](/4.11.2)）。

### 1.5.4. WSL：Windows 上的 Linux

Windows Subsystem for Linux 使 Linux 程序能在 Windows 上运行；本课程的例子就是在这个环境中运行的。它有两个设计截然不同的版本：

| | WSL 1（2016） | WSL 2（2019，默认） |
|---|---|---|
| 设计 | 一个 Windows 内核组件把 Linux 系统调用翻译成 Windows NT 调用 | 真正的 Linux 内核运行在由 Hyper-V 管理的轻量级虚拟机中 |
| 兼容性 | 不完整（无容器，缺少部分系统调用） | 与 Linux 系统调用完全兼容，支持 systemd、Docker、GPU 计算 |
| Linux 文件 | 存放在 Windows 文件系统中 | 存放在虚拟磁盘文件（`ext4.vhdx`）内的 ext4 文件系统中 |
| Windows 文件 | 访问快 | 经由 `/mnt/c`，通过 9P 网络文件协议提供：慢得多 |

在 WSL 2 中，`mount` 显示了这两个世界：

```text
/dev/sdd on / type ext4 (rw,relatime,discard,errors=remount-ro,data=ordered)
C:\ on /mnt/c type 9p (rw,noatime,aname=drvfs;path=C:\;uid=1000;gid=1000;...)
```

实际的规则来自这种设计。项目和数据要放在 Linux 文件系统内（主目录，而不是 `/mnt/c/Users/...`）：`git`、编译器和包管理器等要访问大量小文件的工具在那里要快许多倍。虚拟机会获得主机内存的一部分（默认为一半），并按需增长其虚拟磁盘；限制在 `%UserProfile%\.wslconfig` 中设置。CUDA 程序可通过半虚拟化驱动使用 GPU。Microsoft 于 2025 年公开了 WSL 的源代码；内核本身一直是开源的。虚拟机怎样把整个操作系统作为客户机运行，见 [4.11.9](/4.11.9)。

## 小结

- 操作系统管理硬件并提供抽象（进程、地址空间、文件）；它的内核以完全的特权运行。它的工作分为虚拟化、并发和持久性，保护贯穿始终。
- 批处理系统、多道程序设计和分时导致了 Unix，它的思想（小工具、文件、管道、可移植的内核）在 Linux、macOS 和 POSIX 标准中延续。
- 处理器在用户态运行用户程序，在内核态运行内核。控制权只能通过异常进入内核：中断（异步，来自设备）、陷阱（有意为之，用于系统调用）、故障（可恢复的错误，如缺页）和终止。
- 系统调用是带有服务编号、参数放在寄存器中的陷阱；库包装函数把错误转换为 `errno`。一次系统调用的开销约相当于一百次函数调用，所以 I/O 要做缓冲，vDSO 也因此存在。
- Linux 是由模块和 eBPF 扩展的宏内核。发行版增加用户空间；systemd 启动其余一切。WSL 2 在轻量级虚拟机中运行真正的 Linux 内核；数据要放在它的 ext4 文件系统内。
