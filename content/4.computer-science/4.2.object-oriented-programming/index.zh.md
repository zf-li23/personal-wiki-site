[程序设计基础](/4.1)关心的是"怎么算"：把问题分解成步骤，用变量、分支、循环和函数写出算法。程序变大之后，难点逐渐从算法转移到组织：成百上千个函数共享一堆数据，任何一处改动都可能波及全局。**面向对象编程**关心的是"怎么看"：先把问题领域中的事物抽象成**对象**，让每个对象自己维护数据、提供服务，再让对象相互协作完成任务。本课程以 C++ 为主、Python 为对照，讨论这种组织程序的方式：它的核心思想**抽象**与**封装**，实现这些思想的语言机制，以及怎样用这些机制设计出易于修改和扩展的程序。课程的最后一章讨论今天写程序的另一半现实：大量代码由 AI 生成、修改和审查。

各章的主线是从单个类走向类与类的关系，再走向成熟的设计。课程先比较面向过程与面向对象两种**编程范式**，并说明一个由多个文件组成的 C++ 程序怎样经过编译、链接和构建变成可执行文件。接着是类与对象的基本机制：**类**用访问控制把接口与实现分开；构造函数与析构函数让对象的初始化与清理自动发生，由此得到 C++ 资源管理的核心惯用法 **RAII**；运算符重载让用户定义的类型像内置类型一样使用；引用、复制与移动则决定了资源的所有权在对象之间怎样传递。然后讨论类之间的关系与通用性：组合与**继承**是两种复用方式，**虚函数**在运行时选择调用哪个实现，从而实现**多态**；**模板**提供了另一种在编译时实现的多态，即**泛型编程**。建立在模板之上的标准库（容器、迭代器与算法，字符串、流与正则表达式，函数对象、lambda 与智能指针）展示了这些机制在大规模代码中的用法。**设计模式**一章以一个贯穿的例子说明怎样组合这些机制应对需求的变化，并从中提炼出开闭原则等设计原则。最后一章用"**编程智能体** = 模型 + **harness**"这一框架讨论 AI 辅助编程的模型、工具、工作流与风险。

本课程承接[程序设计基础](/4.1)：那里的**结构体**是类的前身，那里的**指针**与动态内存在这里由 RAII 和智能指针管理。标准库容器背后的数据结构怎样实现、复杂度从何而来，是[数据结构与算法](/4.3)的内容；正则表达式的形式理论见[形式语言与自动机](/4.8)；需求、架构、测试与版本控制等更大范围的软件设计问题见[软件工程](/4.14)。课程中的 Python 对照部分，也为[Python 科学计算](/4.4)中 NumPy、pandas 等库的对象模型打下基础。

在程序设计基础中我体会到，编程是用机器能看懂的语言来表示这个世界。接下来的问题是：用什么方式表示，才便于人来理解？在"古法编程"（不借助 AI、逐行手写代码）的阶段，人最自然的思考方式大概是面向过程的：先做什么，再做什么。但在复杂的工程实践中，需要另一种思维模式。我认为面向对象编程应当被理解为研究这个世界是怎样组成的：有哪些事物，它们各自知道什么、能做什么，彼此之间是什么关系。这门学科的许多术语在字面上就给出了深刻的信息，"对象""类""继承""封装""接口"都能与实际生活直接联系起来。到了 AI 辅助编程的时代，面向对象显得更加自然：语法细节可以交给 AI，人负责的恰恰是把问题领域拆分成对象、规定它们的职责与接口，再检查 AI 写出的实现是否符合这样的设计。

不过在古法编程的阶段，这门课的语法细节确实让我头疼：构造与析构的时机、拷贝与移动的规则、模板的报错信息，往往比面向对象的思想本身更费精力。C++ 在 C 的基础上为面向对象提供了直接的语言支持，同时保留了对内存和性能的控制，这也正是它复杂的原因。Python 则把"一切皆对象"贯彻到底：整数、函数、类本身都是对象，配合**鸭子类型**，许多在 C++ 中需要专门机制的设计写起来轻得多。因此本课程在 C++ 之外同时给出 Python 的代码，两相对照，更容易看清哪些是面向对象的思想，哪些是 C++ 特有的机制。
