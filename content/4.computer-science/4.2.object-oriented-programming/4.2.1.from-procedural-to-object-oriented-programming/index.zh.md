[4.1 程序设计基础](/4.1)关心的是"怎么算"：把问题分解成步骤，用变量、分支、循环和函数写出算法。程序变大之后，难点逐渐从算法转移到组织：成百上千个函数共享一堆数据，谁都可以修改，任何一处改动都可能波及全局。面向对象程序设计关心的是"怎么看"：先把问题领域中的事物抽象成对象，让每个对象自己维护数据、提供服务，再让对象相互协作完成任务。本章是这门课的导论：介绍编程范式的概念，比较面向过程与面向对象两种组织程序的方式，讨论抽象与封装这两个贯穿全课程的思想，最后说明为什么用 C++ 和 Python 来学习它们。后面各章依次展开：[4.2.2](/4.2.2) 讲多文件程序的编译与构建，[4.2.3](/4.2.3)–[4.2.6](/4.2.6) 讲类与对象的基本机制，[4.2.7](/4.2.7)–[4.2.9](/4.2.9) 讲继承、多态与泛型，[4.2.10](/4.2.10)–[4.2.12](/4.2.12) 讲标准库，[4.2.13](/4.2.13) 讲设计模式，[4.2.14](/4.2.14) 讨论 AI 辅助编程。

## 1.1. 编程范式

### 1.1.1. 什么是编程范式

同一个问题可以用很不相同的方式组织成程序。例如统计一段文本中各单词出现的次数：可以写一个循环，逐个读入单词、在表中查找并加一；也可以把文本看成单词的序列，用"分组再计数"这样的组合操作一步写出；还可以设计一个"词频表"对象，让它负责接收单词并回答查询。这三种写法背后是三种不同的思维模型。

**定义 1.1.1（编程范式）** 程序设计中组织计算与数据的基本风格和思维模型称为**编程范式**。它决定了程序由什么基本单元构成、单元之间怎样组合与通信。

常见的范式如下表。它们并不互斥：现代主流语言大多是多范式的，C++ 与 Python 都同时支持面向过程、面向对象和一定程度的函数式编程。

| 范式 | 基本单元 | 核心思想 | 典型语言或场景 |
|---|---|---|---|
| 面向过程（过程式） | 过程（函数） | 把任务分解为一系列步骤，自顶向下、逐步求精 | C、Fortran；C++、Python 的函数部分 |
| 面向对象 | 对象（类） | 数据与操作封装在一起，对象之间相互协作 | C++、Java、C#、Python |
| 函数式 | 函数（无**副作用**） | 用函数的组合与变换描述计算，避免可变状态 | Haskell、OCaml；C++ 的 lambda 与 ranges、Python 的推导式 |
| 逻辑式 | 事实与规则 | 描述"是什么"，由推理机求解 | Prolog、Datalog |
| 泛型 | 参数化的类型与算法 | 算法与具体类型解耦 | C++ 模板、Java 泛型 |

面向过程和面向对象都属于命令式编程：程序是一系列改变状态的命令。函数式和逻辑式属于声明式编程：程序描述结果应满足的性质，而不规定具体步骤。

### 1.1.2. 面向过程与面向对象

**定义 1.1.2** 以过程（函数）为基本单元、把程序组织为一组对数据进行加工的函数的编程方式，称为**面向过程编程**；以对象为基本单元、每个对象把数据和操作这些数据的函数封装在一起，程序通过对象之间的相互调用完成任务的编程方式，称为**面向对象编程**。

两者的区别首先在于数据与操作的关系。面向过程的程序中，数据是被动的：结构体只是存放数据的容器，任何函数都可以读写它。面向对象的程序中，数据是主动的：对象自己决定外界能对它做什么，外界只能"请求"对象完成某项服务（调用它的成员函数），而不能直接改动它的内部。

| | 面向过程 | 面向对象 |
|---|---|---|
| 思考的出发点 | 解决问题需要哪些步骤 | 问题中有哪些事物，它们各负责什么 |
| 程序的结构 | 函数调用层次（自顶向下分解） | 对象及其协作关系 |
| 数据与操作 | 分离：数据结构 + 操作它的函数 | 结合：类 = 数据 + 操作 |
| 修改的影响 | 数据结构一变，所有用到它的函数都要检查 | 只要接口不变，内部实现可以自由修改 |
| 擅长 | 算法、数值计算、顶层业务流程 | 大型系统、需要长期演化和复用的代码 |
| 主要关心 | 计算机的运行效率："怎么算" | 程序员的开发效率："怎么看" |

面向对象并不否定面向过程：对象的每个成员函数内部仍然是顺序、分支、循环构成的过程；面向对象改变的是过程之上的组织方式。这门课的内容可以看成一级级的台阶，每一级都在更高的层次上实现复用：

| 台阶 | 复用的是什么 | 章节 |
|---|---|---|
| 面向过程的 C/C++ | 具体操作（函数） | [4.1](/4.1) |
| 类与对象 | 数据与操作的组合 | [4.2.3](/4.2.3)–[4.2.6](/4.2.6) |
| 组合与继承 | 已有的类 | [4.2.7](/4.2.7) |
| 虚函数与多态 | 统一接口下的不同实现 | [4.2.8](/4.2.8) |
| 模板与泛型编程 | 与类型无关的源代码 | [4.2.9](/4.2.9)–[4.2.12](/4.2.12) |
| 设计模式 | 解决一类设计问题的方案 | [4.2.13](/4.2.13) |

## 1.2. 抽象

### 1.2.1. 抽象的含义

人们用语言思考：数学用符号系统与推理论证表达思想，自然语言用词汇、语法与语用表达思想，程序设计语言则提供了第三种表达方式。面向对象方法的一条基本信念是：人类在认识世界中形成的普遍有效的思维方法，在软件开发中也应当适用；程序的结构应尽量贴近人们描述问题的习惯，而不是迫使人们按机器的方式思考。其中最基本的思维方法就是抽象。

**定义 1.2.1（抽象）** 从许多事物中舍弃个别的、非本质的特征，抽取共同的、本质的特征，这一思维过程称为**抽象**。

什么是"本质"取决于要解决的问题。例如给"鸟"下定义：如果抽取"会飞、有翅膀、有两条腿"，鸵鸟和企鹅就不是鸟了；生物学的定义抽取的是"恒温、卵生、体表被覆羽毛、前肢特化为翼"等特征。对一个航班订票系统，"乘客"只需要姓名、证件号和联系方式，身高体重是非本质的；对一个医疗系统则恰恰相反。抽象总是相对于目的的：好的抽象让与目的无关的细节消失，让相关的性质一目了然。

### 1.2.2. 过程抽象与数据抽象

**定义 1.2.2** 任何一个完成确定功能的操作序列，其使用者都可以只关心它做什么、而不关心它怎么做，把它看作一个整体，这称为**过程抽象**。根据施加于数据上的操作来定义**数据类型**，并规定数据的值只能通过这些操作来修改和观察，这称为**数据抽象**。

过程抽象就是函数：调用 `std::sort(v.begin(), v.end())` 的人不需要知道它用的是哪种排序算法。数据抽象则把"数据"理解为"值 + 允许的操作"。数学家早就这样看待数据：整数集 $\mathbb{Z}$ 连同加法和乘法构成环，而不只是一堆数；程序设计语言中的类型也是如此：

| 表达式 | C++ | Python | 说明 |
|---|---|---|---|
| `3 / 4` | `0` | `0.75` | C++ 的整数除法得整数（向零取整）；Python 的 `/` 总是真除法 |
| `3 // 4` | 不是表达式（`//` 开始注释） | `0` | Python 的整除（向下取整） |
| `3.2 / 4.0` | `0.8` | `0.8` | 浮点除法 |
| `'a' * 3` | `291`（`char` 先提升为 `int`，`'a'` 的编码是 97） | `'aaa'`（字符串重复） | 同样的写法，类型不同则含义不同 |

于是可以说：类型 = 数据的存储与表示 + 数据支持的操作。内置类型的操作由语言规定；面向对象编程让程序员用同样的方式定义新类型，这就是[类](/4.2.3)。

## 1.3. 对象与封装

### 1.3.1. 对象

**定义 1.3.1（对象）** **对象**是对现实世界中事物的抽象描述，它可以是有形的实体（一本书、一个学生），也可以是无形的概念（一次借阅、一门课程）。一个对象具有：

- 状态（静态特征）：可以用数据描述的属性，如书名、作者、是否已借出；
- 行为（动态特征）：对象能提供的服务，如借出、归还、查询；
- 标识：区别于其他对象的身份，即使两本书的属性完全相同，它们也是两个对象。

对象是属性与服务的结合体。具有相同属性和服务的一组对象由同一个类描述，对象是类的实例（[4.2.3](/4.2.3)）。

### 1.3.2. 封装与信息隐藏

**定义 1.3.2（封装）** 把数据和操作数据的函数组合成一个整体，并对外隐藏内部的实现细节、只通过规定的接口与外界交互，称为**封装**。其中"对外隐藏实现细节"这一方面称为**信息隐藏**。

封装带来两个好处。第一，对象可以维护自己的不变式（invariant），即在对象整个生命期中始终成立的条件：例如账户余额永远不为负、分数的分母永远为正。只要所有修改都经过对象自己的成员函数，检查就只需写在一处。第二，实现可以独立演化：使用者只依赖接口，类的作者可以替换内部的数据结构而不影响任何调用者。

下面用一个银行账户比较两种写法。面向过程的版本中，账户是一个只存放数据的结构，任何代码都可以直接改动余额：

```cpp tab
#include <iostream>

struct Account {
    double balance;
};

bool withdraw(Account& acc, double amount) {
    if (amount <= 0 || amount > acc.balance) return false;
    acc.balance -= amount;
    return true;
}

int main() {
    Account acc{100.0};
    withdraw(acc, 30.0);
    acc.balance = -1e9;  // nothing prevents breaking the rule "balance >= 0"
    std::cout << acc.balance << '\n';
}
```

```python tab
from dataclasses import dataclass


@dataclass
class Account:
    balance: float


def withdraw(acc: Account, amount: float) -> bool:
    if amount <= 0 or amount > acc.balance:
        return False
    acc.balance -= amount
    return True


acc = Account(100.0)
withdraw(acc, 30.0)
acc.balance = -1e9  # nothing prevents breaking the rule "balance >= 0"
print(acc.balance)
```

面向对象的版本把余额设为私有，只能通过 `deposit` 和 `withdraw` 修改，规则"余额非负"由类自己保证：

```cpp tab
#include <iostream>
#include <stdexcept>

class Account {
public:
    explicit Account(double initial) : balance_(initial) {
        if (initial < 0) throw std::invalid_argument("negative balance");
    }
    void deposit(double amount) {
        if (amount <= 0) throw std::invalid_argument("non-positive deposit");
        balance_ += amount;
    }
    bool withdraw(double amount) {
        if (amount <= 0 || amount > balance_) return false;
        balance_ -= amount;
        return true;
    }
    double balance() const { return balance_; }

private:
    double balance_;  // invariant: balance_ >= 0
};

int main() {
    Account acc(100.0);
    acc.withdraw(30.0);
    // acc.balance_ = -1e9;  // compile error: balance_ is private
    std::cout << acc.balance() << '\n';  // 70
}
```

```python tab
class Account:
    def __init__(self, initial: float) -> None:
        if initial < 0:
            raise ValueError("negative balance")
        self._balance = initial  # invariant: _balance >= 0

    def deposit(self, amount: float) -> None:
        if amount <= 0:
            raise ValueError("non-positive deposit")
        self._balance += amount

    def withdraw(self, amount: float) -> bool:
        if amount <= 0 or amount > self._balance:
            return False
        self._balance -= amount
        return True

    @property
    def balance(self) -> float:
        return self._balance


acc = Account(100.0)
acc.withdraw(30.0)
print(acc.balance)  # 70.0
```

C++ 的 `private` 由编译器强制执行；Python 没有真正的私有成员，单下划线开头的 `_balance` 只是"内部使用"的约定，`@property` 让 `balance` 可以像属性一样读取却不能直接赋值（[4.2.3](/4.2.3)）。两种语言的共同点是：接口（`deposit`、`withdraw`、`balance`）与实现（一个浮点数，将来也可以换成以分为单位的整数）分开了。

### 1.3.3. 面向对象的三个基本特征

| 特征 | 含义 | 本课程中的位置 |
|---|---|---|
| 封装 | 数据与操作结合，隐藏实现 | [4.2.3](/4.2.3)–[4.2.6](/4.2.6) |
| 继承 | 在已有类的基础上定义新类，复用并扩展其属性与行为 | [4.2.7](/4.2.7) |
| 多态 | 同一接口在不同对象上有不同的行为 | [4.2.8](/4.2.8)、[4.2.9](/4.2.9) |

需要注意，"面向对象"不等于"把所有代码都塞进类里"。一个只有静态函数的类、一个暴露全部数据成员并提供一堆 `get`/`set` 的类，都没有得到封装的好处。判断一个设计是否面向对象，要看职责是否分配给了掌握相应数据的对象、接口是否稳定而实现是否被隐藏。

## 1.4. 好程序的标准

本课程的目标是写出更好的软件。经典的标准有三条：

- 简单性：程序短小、容易管理。函数和类各自只做一件事，越长越复杂的代码越难维护和调试。
- 清晰性：容易理解，无论对人还是对机器。对人而言，命名、结构和注释能让读者一眼看出代码的意图；对机器而言，程序不应依赖未定义或未指明的行为。
- 普遍性：在广泛的情形下都能正确工作，并且容易修改以适应新情况，包括边界情况和错误输入。

"对机器清晰"有具体的含义。C++ 标准对某些写法不规定结果，例如在同一个表达式中两次修改同一个变量：

```cpp
#include <iostream>

int main() {
    int i = 1;
    // int j = i++ + i++;  // undefined behavior: two unsequenced modifications of i
    int j = i + (i + 1);    // say what you mean instead
    i += 2;
    std::cout << i << ' ' << j << '\n';  // 3 3
}
```

带注释的那一行属于**未定义行为**：标准对它的结果不作任何要求，不同编译器、不同优化级别可能给出不同结果，甚至让程序的其他部分出错。清晰的程序不写这种代码。

## 1.5. 为什么用 C++ 与 Python

### 1.5.1. C++

C++ 由 Bjarne Stroustrup 在 C 语言的基础上发展而来，至今仍是系统软件、游戏引擎、数据库、浏览器、高性能计算以及深度学习框架底层的主要语言。用它学习面向对象有几个原因：

- 零开销抽象（zero-overhead abstraction）：类、模板等抽象机制在不使用时不产生额外开销，使用时也不比手写的等价代码更慢。抽象与效率可以兼得。
- 确定的对象生命周期：对象何时创建、何时销毁由程序的结构精确决定，析构函数在确定的时刻运行。这使 C++ 能用对象管理内存、文件、锁等一切资源（[4.2.4](/4.2.4)），也迫使学习者真正理解对象的创建、复制与销毁（[4.2.6](/4.2.6)）。
- 贴近机器：可以直接操作内存与硬件，能看清每一种抽象在底层是怎样实现的（如虚函数表，[4.2.8](/4.2.8)）。

代价是复杂：语言规则多，没有**垃圾回收**，需要自己管理资源；越界访问、**悬垂指针**等错误会导致**未定义行为**，这也是近年业界重视"内存安全"、在新项目中部分转向 Rust 等语言的原因。现代 C++ 的发展方向正是用更安全的抽象减少这类错误：C++11 引入了移动语义、智能指针、lambda 与 `auto`，此后每三年一个新标准，C++20 加入了 concepts、ranges、模块与协程，C++23 加入了 `std::print`、`std::expected` 等，C++26 的草案已加入静态反射与契约。本课程以 C++20/23 为准，提倡使用标准库容器与智能指针、避免裸露的 `new`/`delete`。

### 1.5.2. Python

Python 走的是另一条路：**动态类型**，自动内存管理，语法简洁。它的面向对象机制更灵活也更"宽松"：没有强制的访问控制，可以在运行时给对象添加属性，判断一个对象能否使用只看它是否提供了所需的方法，而不看它属于哪个类。两种语言对照学习，能把"面向对象的思想"与"某种语言的实现细节"区分开。

| | C++ | Python |
|---|---|---|
| 类型检查 | 静态（编译期） | 动态（运行期）；类型标注只供工具检查 |
| 变量 | 一块存放值的内存 | 绑定到对象的名字 |
| 赋值 `b = a` | 复制值（[4.2.6](/4.2.6)） | 让 `b` 指向同一个对象 |
| 对象的销毁 | 确定：离开作用域或 `delete` 时 | 引用计数归零或被垃圾回收时 |
| 访问控制 | `public`/`protected`/`private`，编译器强制 | 命名约定（`_x`、`__x`） |
| 运算符重载 | `operator+` 等成员或非成员函数 | 特殊方法 `__add__` 等 |
| 多态 | 虚函数、模板 | 动态派发，所有方法都可被覆盖 |

本课程"轻语法、重思想"：每个概念先讲清它要解决的问题，再给出 C++ 与 Python 的实现；只属于一种语言的机制（C++ 的引用、移动语义与 RAII，Python 的特殊方法与上下文管理器）在相应位置单独说明。

## 1.6. Python 中一切皆对象

在 Python 中，整数、字符串、函数、类、模块都是对象：每个对象都有标识（`id`）、类型（`type`）和值，都可以赋给变量、放进容器、作为参数传递。类本身也是对象，它的类型是 `type`。

```python
def greet(name: str) -> str:
    return f"hello, {name}"


print(type(42), (42).bit_length())  # <class 'int'> 6
print(type(greet), greet.__name__)  # <class 'function'> greet
print(type(int), type(type))        # <class 'type'> <class 'type'>

f = greet                  # a function is a value: bind another name to it
print(f("OOP"))            # hello, OOP
print(isinstance(3, object), isinstance(int, object))  # True True

a = [1, 2]
b = a                      # b names the same list object
print(a is b, id(a) == id(b))  # True True
```

C++ 中的"对象"含义更窄：标准把对象定义为一块具有类型、大小和生命期的存储区域，`int x;` 中的 `x` 就是一个对象，但函数和类不是对象。两种语言用同一个词指不同的东西，这一点在[4.2.6](/4.2.6)讨论赋值语义时还会遇到。

## 小结

- 编程范式是组织程序的思维模型；面向过程以函数为单元、数据与操作分离，面向对象以对象为单元、数据与操作封装在一起。
- 抽象是舍弃非本质、抽取本质；过程抽象得到函数，数据抽象得到类型。类型 = 表示 + 操作。
- 对象有状态、行为与标识；封装把数据与操作结合并隐藏实现，使对象能维护自己的不变式、让实现独立演化。
- C++ 提供零开销抽象与确定的对象生命周期，Python 提供动态而灵活的对象模型；本课程用两种语言对照讲解同一套思想。
